# BLACK 语音交互对照审核

日期：2026-10-15。对象：v1.7.17 发布前审核的源码，不代表用户手机已经安装或完成验收。

## 对照依据与结论

字节官方对 [Seeduplex](https://seed.bytedance.com/zh/blog/introducing-seed-full-duplex-speech-llm-attentive-listening-robust-interference-suppression-enabling-more-natural-interaction) 的说明将同时听说、忽略无关人声、根据语音及语义判断接话时机作为主要能力。后续 [SeedRealtime](https://seed.bytedance.com/zh/blog/seedrealtime-audio-visual-full-duplex-llm-released-toward-omni-modal-natural-interaction?view_from=homepage_tab) 将连续音视频交互统一到模型中。本轮仅对照其中的语音体验，不增加摄像头功能，不调用豆包/火山服务。

**结论：完成了当前分层架构内的修复和个人声纹接入；没有证据证明已达到豆包同等的自然度、时延及复杂声场可靠性。** 豆包的私有模型权重、训练数据和完整实现不可从上述公开介绍得到，不能把本次工程对照说成完整复刻或真人对比验收。

## 功能对照

| 项目 | BLACK 当前实现和证据 | 仍存在的边界 |
| --- | --- | --- |
| 同时听与说 | 一个麦克风持续采集；AudioTrack 的实际 PCM 作为 AEC3 参考；候选只暂停，不直接销毁回答 | 是并发工程链路，不是原生音频—语义联合模型 |
| 回声与误打断 | 回声处理 → Silero 人声候选 → CAM++ 主人验证 → 模型判断是否接话；VAD 不直接取消旧请求 | 未对 ColorOS 外放声场做实测；没有神经目标说话人分离，不能保证多人重叠下分离成功 |
| 专属用户登记 | 三段 BLACK 开头的不同语句，长/短/唤醒特征分别建库；第四次独立唤醒回读通过才保存 | 实际用户尚未登记验收；感冒、远场、方言与极短音节的群体误识率未校准 |
| 仅主人唤醒 | 神经关键词时间戳截取实际音频，再与个人 BLACK 模板比较；实际 KWS/VAD/CAM++ 联合测试通过 | 合成声测试不代表真人效果；声纹不能防范全部重放、克隆或混合音频 |
| 仅主人接话/打断 | 每一新音频包独立比较；不复用先前身份，也不把旧主人 PCM 拼入新尾音；公开真人留出片段测试通过 | 不足 320 ms 的通用片段不会放行；同一包内部的混合说话人仍可能误判 |
| 慢速表达与停顿 | ASR 分段累计到同一草稿；只读模型选择 respond / wait / ignore；wait 不反复提交不变草稿 | 模型看到转写及上下文，而非完整声学韵律，判停自然度尚未做真人评测 |
| 忽略旁人 | 未验证音频不进 ASR/Agent；不撤销已有只读判定；保存前面已经确认的本人文字 | 持续嘈杂可能延迟接话；“本人在跟别人讲话”仍依赖模型语义判断 |
| 单独唤醒回应 | 已验证的裸 BLACK 直接进原 Agent，省一次判停请求；没有第二个本地“我在” | 仍需模型联网生成和系统 TTS；模型错误或网络故障时不能保证立即答应 |
| 文字、工具与上下文 | 与文字聊天共用同一会话、原模型及全部授权工具；文字生成时即展示；工具回执保持独立消息 | 工具执行的外部成功率受目标软件、网络和已授权权限影响，不由语音测试保证 |
| 播放可靠性 | 顺序文件合成、中文音色可用性尝试、受控重连一次；真实 AudioTrack 播放/暂停/恢复及 TTS 故障测试通过 | 测试 TTS 不是 ColorOS 原厂引擎；回答完成后才启动合成，时延与表现力仍不同于端到端流式语音 |
| 异常与取消 | 首次唤醒的等待/错误统一恢复；取消/删除先同步作废登记凭证；回答结束重新计算续听窗口 | Android 强行停止、撤回麦克风或 OEM 杀服务后，不能承诺持续唤醒 |

## 本轮发现并处理的问题

1. Kotlin 默认关键词 boost 与离线检查不一致，BLACK 接长句的测试失败：显式统一参数后原测试重测通过，未降低声纹门槛。
2. 长语音模板不能证明短 BLACK 可用：增加独立关键词模板和未参与建库的回读，失败不保存。
3. 旧身份沿用可污染下一位说话人的短尾音：替换为独立音频包，不借用旧人声。
4. 未认证声音可撤销判停：改为只暂缓应用，主人新音频通过后才撤销旧结果。
5. 首次 wait/error 可停在验证状态：统一超时恢复与有限的只读重试。
6. 异步停止登记存在落盘竞态：取消/删除与原子保存共享凭证及锁。
7. 旁人尾音可能删除本人前半句：只封存已认证音频的识别结果，不注入旁人音频。
8. 3.2 秒一到就换登记段会切断朗读：达到最少人声时长后，等用户停顿再换段。
9. 长回答结束后续听窗口可能立即过期：完成播放时续期，但不清空正在收集的新发言。

## 实际验证与未完成的验收

- 全量 Node：546 项；JVM：55 项；TypeScript、整个 App 的 Android Kotlin 编译通过。
- 自有 Android 15 x86_64 模拟器：11 项 instrumentation 通过。测试运行真实本地模型、Android 加密存储、系统 TTS 接口、AudioTrack 和公开网页请求。
- 样本：模型作者的公开同人/异人录音，以及 Windows 系统合成语音；素材仅在 androidTest 内，发布检查禁止其进入正式 APK。
- 这些测试**未使用用户本人声纹、实体手机麦克风或豆包同条件 A/B**；未调用付费模型评测真人判停正确率，也没有伪造唤醒成功率、打断时延或群体误识率。

手机验收应在安装包含本次改动的新版本后重新登记：本人/旁人分别喊 BLACK；本人慢速表达和中途修正；外放时打断及旁人插话；长回答后直接接下一句；锁屏；ColorOS 原厂中文 TTS 的失败恢复。需要记录实际结果才能把对应项从“开发验证”升级为“手机验收通过”。
