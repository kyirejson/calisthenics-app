# MAX V1.8 通用手机控制实现与验收

日期：2026-10-16。源码配置为 1.8.0 / Android 32；发布事实以 GitHub Releases 为准。本文不把已构建、模拟控件通过或源码已同步等同于三项真机验收全部完成。

本文保留 V1.8.0 的实现事实。后续零尺寸窗口、语音恢复、提醒和缓存改动见 [2026-10-17 可靠性审计](max-reliability-and-token-audit-2026-10-17.md)。

## 实现范围

微信发消息、打开浏览器、地图找路线是验收样例，不是 App 白名单。模型可动态发现当前用户空间内安装且可启动的所有应用，选择真实入口，自主观察、规划和连续操作。文字和语音使用原有模型 API、完整上下文与同一工具循环；没有本地关键词意图分类器、联系人匹配器、路线选择器、固定导航脚本或工具轮次上限。

工具：

| 工具 | 真实能力 |
| --- | --- |
| `read_phone_status` | 独立授权、无障碍连接、锁屏、Android API 和实际系统动作 |
| `find_apps` | 动态应用列表，可空查询分页；不是默认上传全部安装列表 |
| `open_app` | 真实可启动 Activity，或目标应用接受的公开链接；随操作回读实际界面 |
| `read_phone_screen` | 当前页面控件、文字、坐标、真实节点动作和分页；按需本机 OCR |
| `phone_ui_action` | 点击、触摸、长按、填入模型决定的完整正文、提交、滚动及节点实际支持的动作 |
| `phone_gesture` | 基于真实画面的单点、滑动、长按与多指路径 |
| `phone_global_action` | 系统当前提供的返回、主页、最近应用、通知等动作 |

模型可以自行向真实收件对象发送用户明确要求的内容，不逐步要求手工点击；重名、目标或正文缺失时才澄清。目标与路线由模型判断，代码不替模型作语义决策。没有绕过登录、锁屏、系统授权或生物认证的工具。

Android 启动器查询用 MAIN/LAUNCHER `<queries>`，没有索取 `QUERY_ALL_PACKAGES`。[官方包可见性说明](https://developer.android.com/training/package-visibility/declaring)

## 一个执行引擎，不复制音乐控制

`modules/uncover-device` 负责系统实际能力。`PhoneUi` 是音乐和通用控制共享的唯一节点、快照、手势与观察实现。生产保留既有 `uncover.music.MusicAccessibilityService` Android 组件，只作为音乐特定显示器/授权校验的薄适配器；不再保留另一套旧节点遍历和点击代码。

通用授权默认关闭，旧音乐授权不扩大为全机授权。用户从 MAX 服务设置单独同意后，才允许通用发现与读屏。服务只保留内容变更事件的包名和时序用于观察等待，不在待机中持续采集文字。撤权、清理手机操作记录或清除全 App 本机数据会停止当前通用任务并撤销授权。音乐原有独立同意仍独立保留。

通用工具操作真实主屏幕，有可随时停止的任务通知；结束后保持用户请求打开的应用，不自动把 MAX 拉回前台。可选音乐后台虚拟屏幕继续走原来的 Shizuku 路由和显示器校验，不自动降级到主屏。此版本不宣称所有 App 均可在隐形后台操作。前台服务也不等于取得任意后台启动的系统许可。[Android 后台 Activity 启动规则](https://developer.android.com/guide/components/activities/secure-bal)

## 操作事实、重试与取消

- 每次用户消息和执行代次独立绑定；快照校验包名、显示器、窗口和页面顶部上下文，节点另校验路径及指纹。切换了会话，即使仍有同名“发送”按钮，也拒绝旧引用并要求重新观察。
- 先持久化操作编号、请求编号和规范化参数 SHA-256，再派发物理操作。回执不另存整段正文、联系人或完整屏幕。
- 同一请求、同一编号与相同参数直接返回原回执；不同参数不能冒用原编号。崩溃留下的未决动作标记 `uncertain_operation/mayHaveExecuted`，不自动再次点击。
- “系统接受动作”与“真实界面观察”独立返回；观察失败不抹除已发生的发送。工具从不把 accepted 自动提升为“已送达”或“导航完成”，由模型核实真实结果。
- 取消会失效该执行代次；已派发动作的迟到事实仍保留，后续动作不得继续。只读识字结果不能在取消后恢复模型执行。
- 仅保留最近 32 个请求的辅助回执；当前请求不限制步骤数。对话本身仍保留此前工具事实。

第三方页面、聊天消息与工具结果是外部数据，不可改写用户意图或产生付款/发送等新授权。这是执行所有权与外部内容隔离，不是用业务规则替代模型思考。

## 自绘文字的本机识别

默认只读无障碍节点。模型设置 `visualText=true` 时，在本机通过系统截图 API 和固定版本 ML Kit 中文/拉丁识字读取自绘文字与坐标。截图不写文件、不上传；已识别的密码节点区域先遮盖。识别后再次核验页面/权限/执行归属，取消时不返回迟到结果；系统拒绝受保护窗口时原样报错，不尝试绕过。

使用捆绑模型，不依赖用户安装 Google Play 或首次联网下载识字模型；不会接入第二个云视觉服务。识字有误差，也不等于理解任意图标、图片、游戏或纯画布语义，不能宣称“所有 App 所有页面百分百可用”。[ML Kit 官方 Android 接入](https://developers.google.com/ml-kit/vision/text-recognition/v2/android)、[Android AccessibilityService 截图和动作能力](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService)

## 仍需真实环境验收的标准

1. 已登录微信，模型自主查找指定人或群、核对会话与正文并发送；开发侧不能擅自向私人联系人试发，等待用户确认文件传输助手或专用目标。
2. 真实手机浏览器打开；模拟器 Chrome 已实测，但不是 ColorOS 厂商策略全覆盖。
3. 高德/腾讯/百度地图实际搜索地点、比较并选择路线；这次没有对应目标 App 的实际路线选择证据，不能用系统设置、Google Maps 或模拟页面代替。

正式签名产物可用于上述手机验收，不制作另一个 applicationId 的用户测试包。尚未完成的验收不会写成“全部通过”；正式上传应在真实验收结果或用户对未验收范围明确知情后进行。

## 分发边界

本项目当前自主分发 GitHub APK。普通模型助手的自主无障碍规划/执行不应宣称符合 Google Play 的自动化政策；这不是 Android 禁止所有界面操作，也不是可以绕过权限的理由。[Google Play 无障碍 API 政策](https://support.google.com/googleplay/android-developer/answer/10964491?hl=en-EN)
