# BLACK：本地回声处理与模型自主回应

这是 v1.7.16 的实现记录。当前工作区的主人验证、语义判停及可恢复播放以 [后续重构说明](voice-owner-turns-2026-10-15.md) 为准；不要把本页旧的声学检测流程当作新版打断授权逻辑。

本轮按用户更正后的范围实施：不接豆包/火山引擎服务，不增加账号、密钥或费用，保留现有 DeepSeek Agent 及全部已授权工具。

## 已确认的问题

- v1.7.15 的旧处理把残余回声交给人声检测，连续五帧便立即停止播放器。人声检测不识别声源，因此自己的回答也能触发取消、转写和下一轮回答。
- 旧测试只覆盖少量固定线性回声；扩展到不同短句、削波和 320 ms 延迟后可以复现误触发。不能把旧测试通过视为真实外放问题已解决。
- 本地固定“我在”和提示词中的“本地已确认唤醒”与用户要求不符，现已一起移除，包括音频、生成器、来源文件和界面占位提示。BLACK 唤醒现在作为一次输入交给现有模型。

## 实现

1. 唯一 AudioRecord 采集，优先使用硬件单调时钟；没有硬件时间戳时沿样本时钟推进，不再用每次 read 返回的时间冒充采集时间。
2. 唯一 AudioTrack 渲染所有模型回答；以实际播放时间、已播放采样和取消位置建立本地参考，取消后保留已经播放声音的回声尾迹。
3. 本地 WebRTC AEC3 处理录音和参考，使用线性输出保留同时说话的用户声音。10 ms DSP 与 32 ms VAD/ASR 通过固定 10 ms FIFO 衔接，避免采样丢失或累计漂移。
4. 声学相关性检查与人声检测分别工作，搜索最高 512 ms 的播放路径。高度对应本机波形的帧不作为新用户声源。没有播放参考时不做此屏蔽；不按用户说出的词语判断，也不因处于 speaking 状态便停止采集。
5. VAD 的循环状态会在零音频帧后短暂延续。声学阶段已消除的帧不能凭历史置信度触发新的打断。真实插话仍保留预卷音频，并取消旧请求、停止播放和阻止旧结果复活。
6. 模型增加 `continue_listening(reason)` 工具，可自主选择暂不发声。空接口响应依旧是错误，不被冒充成模型主动保持安静。选择倾听后不调用 TTS、不显示空回复气泡、不清上下文；同批其他工具仍执行并保留回执。
7. 独立 AEC3 绕过了完整 APM 的浮点保护，静音滤波尾部会触发极慢的非规格化数运算。按 WebRTC 的 scoped FTZ/DAZ 方式处理，退出 DSP 后恢复原线程设置，不能把此类 CPU 开销误称为模拟器调度误差。
8. 修复旧重采样未冲刷文件尾部的问题，按原音频时长输出完整 PCM，覆盖多种系统 TTS 采样率。
9. 模型完成后停止请求所有权轮询，并隔离已发出的迟到查询；从生成转入播放/倾听不是取消，不能因返回 `active:false` 反过来打断刚开始的回答。

代码仍负责设备状态、采样、保存、取消与工具参数契约，不负责用关键词代替模型判断用户意图。模型收到的是识别文字而非原始音频，因此不能声称它直接听出了音色或拥有原生音频大模型的声学理解。

## 依赖和研究边界

AEC3 使用 BSD-3-Clause 的 WebRTC 算法独立源码提取，固定 Enaium/webrtc-aec3 提交 `2cec2f52e26646f93bd2d5498bbabf59cba18da9`、归档 SHA-256 `3bc3423e71b7280cf96d87b2e429444ed3fee364b94648ce9875ee95b8f485f8`。仅编译本地音频处理，不包含 RTC 网络传输或云端语音。SpeexDSP 仅保留重采样用途，旧三抽头预减法和旧 Speex AEC 不再编译。许可和来源随 APK 提供。

公开资料能够支持“回声处理与对话决策不是同一层”的设计，但不能据此声称掌握豆包 App 的完整私有实现。这里是自主集成的本地链路，不是对其代码或效果的复制。

## 验证与限制

- TypeScript、Node 回归、四 ABI 编译、Android 实际 PCM 播放/取消、生成音频回放测试是不同验收项，分别记录，不互相替代。
- 扩展回放覆盖短句、长答、噪声、压缩、削波、音量变化、延迟变化、长延迟、不同/相同合成音色与两档用户音量；闭环另检查打断后停止播放、保留物理尾声并继续转写。
- 这些测试不读取真人麦克风，不使用用户私有录音或生产 API 密钥。
- 尚不能保证任何机型、距离、房间或外放音量下零误判。ColorOS 真机外放、蓝牙、远场和持续监听耗电仍需独立实测，不宣称已达到豆包完整原生全双工效果。
