# MAX：由模型结束本次语音交流

## 行为范围

- 保持现有 30 秒无活动回待机，不调整计时、AEC、VAD 或打断阈值。
- 正式语音 Agent 自主判断当前用户是否要结束交流；不增加“退下吧”等关键词匹配器。
- 提供语音专用 `end_voice_conversation(reason)` 工具。结束后静默等待 MAX，不额外生成或合成告别语。
- `continue_listening` 仍是本轮不出声但继续听，与结束交流分开。
- 不关闭全局监听，不清除聊天/个人记忆，不取消已经启动的音乐、跑步或业务记录。不新增界面按钮、权限、音频模型或云服务。

## 链路与所有权

1. 只读轮次判断器把完整的结束交流请求交给正式 Agent，而不是当成“无需回答”丢弃。
2. 正式 Agent 结合当前消息及完整上下文选择工具；讨论、引用和历史退出回执不是新的退出指令。
3. 结束工具必须单独调用。与饮食、音乐等混合的一批操作仍执行并完整回报；本批结束选择只返回 `pendingReview`，不提前退出，模型核对结果后再决定。
4. 工具先安排本轮收尾，返回 `standbyScheduled`，不伪称原生切换已经完成。对话投递层随后按原生请求 ID 调用 `standby`，正常保存无声工具轮次。
5. 原生统一状态控制器仅允许当前生成请求退出。切到 WAKE、递增代次并清理输入草稿，服务复用原有 30 秒到期的 KWS 待机入口。录音服务及全局 enabled 保留，因此下一次 MAX 可以继续唤醒。
6. 如果决定退出期间新的说话已经进入，保留新输入而不强制待机；过期请求不能改变新请求、静音状态或停用状态。
7. ASR 提交携带所属输入段，主线程验证当前段；待机后迟到的提交/语义探测不能凭旧内容重启 Agent。旧播放回调仍受请求 ID 与 generation 保护。

## 验证边界

- 初次待机专项验证：TypeScript 检查通过，项目 Node 回归 564/564、语音 Kotlin 单元测试 51/51 通过；原生模块与 Android 测试代码编译通过。同日继续合并 MAX 更名与连续播放后的验证见 `max-voice-continuity-2026-10-16.md`。
- Node 回归覆盖模型自主选择、引语/同词不被代码拦截、工具可用性、无声结束、上下文保留及再次唤醒、混合任务核对、失败反馈、重复投递和过期退出。
- Kotlin 单元测试覆盖精确 30 秒边界、处理/播放期间不超时、退出后仍可采集唤醒、新输入优先、迟到输入/播放隔离、旧请求不能关闭新请求。
- 测试里的模型选择为注入回执，不冒充实际 DeepSeek 语义评测，也不冒充 OPPO Find X8 Pro 真机麦克风验收。
- 包含原生接口变化，需要新版 APK；已发布的 v1.7.22 不会因源代码修改自动获得该功能。
