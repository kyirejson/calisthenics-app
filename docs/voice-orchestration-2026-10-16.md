## 已复现的编排问题

先在旧代码增加两个行为回归，JVM 执行结果为 31 项中 2 项失败：

- `receivingTextIsNotEvidenceOfAudiblePlayback`：仅收到回答文字，尚无播放器起播事件，旧控制器就显示 `speaking`。
- `finishingOutputMustNotEraseConcurrentInput`：旧输出结束，把正在进行的输入候选直接覆盖成普通 `LISTENING`。

此外，旧 Service 用 `listening` 表示采集可用，识别器另有 `outputActive`、跟进计数及 30 秒空闲计时；JS 同时以 300/500 ms 轮询推断任务取消。疑似语音触发 20% 音量并定时恢复，回调未绑定输入候选。播放器已有暂停能力，但没有用于实际会话。

## 唯一会话所有者

`VoiceSessionController` 在 Service 主事件队列上处理状态变化，向其他线程暴露单份不可变 `Snapshot`。Service 装配资源、执行控制器决定的播放保持/取消，并广播快照；不另存一套会话阶段。

快照同时区分以下事实，不把采集与播放强行互斥：

- 资源：是否准备好、麦克风是否被静音、是否停止。
- 输入：待唤醒、倾听、疑似声音、持续语音及转写、语义判断。
- 输出：空闲、生成回答、合成、实际播放、等待后续音频。
- 所有权：请求 ID、轮次 generation、输入片段 ID。
- 输入草稿与可恢复保持：`draft`、`held`。

识别器中仍有 KWS/ASR 流选择、分段、语义请求去重；合成器仍有队列和工作阶段。这些是模块内部处理进度，不再自行管理会话空闲或用户可见的“正在回答”。播放器的资源 token 与业务轮次 ID 绑定，用来拒绝迟到的音频回调，不是另一套会话控制器。

## 状态与界面

| 实际事件 | 原生阶段 | 展示 |
| --- | --- | --- |
| 等待唤醒 | `wake` | 等待 BLACK 唤醒 |
| 等待/累积用户表达 | `listening` | 正在听你说话 |
| 只读语义判停 | `assessing` | 正在确认你的意思 |
| Agent 生成/调用工具 | `processing` | 正在处理你的请求 |
| 已收到文字但未出声 | `synthesizing` | 正在准备语音 |
| AudioTrack 播放头已消费音频 | `speaking` | 正在回答 |
| 已播片段结束、后续音频尚未到达 | `buffering` | 正在准备后续语音 |

会话中的疑似声音不改成“用户在说话”；达到输入证据条件后，先暂停输出并显示倾听/判断阶段。`held` 期间保留输出所有权，所以停止按钮仍有效。字幕只在实际播放阶段高亮，不把等待合成的文字标成正在朗读。

JS 的 `protocol.ts` 是桥接类型契约；`presentation.ts` 只把原生阶段映射为显示，不再拥有自己的状态机。聊天、设置使用同一映射。输入预览从完整原生快照同步，忽略输入后可正确清除，不只依赖某一种 transcript 事件。

## 打断与判停分离

1. 对采集执行现有 AEC/VAD，连续 5 个 32 ms 人声候选帧启动识别，不永久取消回答，也不改变播放音量。
2. 连续语音达到 8 帧，并有实际 ASR 文字，产生 `hearing` 事件。总控立即保持输出；保留原音频位置及旧轮次，不等 900 ms 静音或联网语义判断完成才暂停。
3. ASR 分段只累积草稿。语义模型仍自主判断 `respond / wait / ignore`。
4. `respond`：取消旧轮次、停止旧播放器，再提交一次累计新输入。旧回调受请求 ID/generation 检查，不能改变新轮次。
5. `wait`：保留草稿和可恢复保持，继续接收补充。不会以半句话执行工具，也不会不断重试同一份不变草稿。
6. `ignore` 或判断失败：解除保持，旧音频从原位置继续，不重新调用 Agent。失败仍保留实际错误和草稿；`ignore` 清除草稿。
7. 没有新转写的噪声片段只结束候选，不清掉之前待补充的草稿。

保持不是永久冻结：总控单一时钟在 30 秒无输入活动时解除保持；有新文字、候选或判停活动会续期。无正在执行的轮次且连续 30 秒无活动时才回到唤醒。持续输出不被识别器自己的空闲计时打断。

上述“人声 + 转写”是可撤销的交互证据，不是身份认证，也不能保证所有手机外放回声都被正确排除。因此只暂停音频，不在声学候选阶段永久销毁模型结果。专属声纹仍未启用。

## 清理与取消

- 删除 Service 的 `listening` 布尔变量、转写副本，改读控制器快照；采集可用明确叫 `captureAvailable`。
- 删除识别器的 `outputActive`、`beginReply/afterReply/listenAgain`、跟进计数和会话空闲计时。
- 删除候选声音降到 20% 音量及 1200 ms 恢复定时器；移除不再使用的 `duck`、播放器音量变量和音量写入。
- 真实接通播放器已有的 pause/resume。保持与恢复不重建合成引擎、不重播前文、不重复工具。
- 删除 JS 的两条所有权轮询，用带服务 epoch、顺序号、请求 ID 的取消事件驱动；新转写撤销旧的只读语义请求。
- native 事件先去重、拒绝退休服务事件，再派发取消；聊天存档加载仍先于对话展示/落盘。
- 初始化尚未加载会话时的取消不写空历史，避免早期事件覆盖保存的上下文。
- 聊天页面只订阅真实配置变化并取消自己拥有的文字请求；删除“任何连接通知都全局中断对话”的入口，避免语音仍播放但 UI 被标成已打断。

`VoiceFrameSource` 是采集输入端口，生产仅使用 `VoiceCaptureDriver`。测试通过该端口回放公开合成 PCM，仍运行真实 AEC/VAD/ASR，不新增第二条生产语音主循环，也不保存用户录音。
