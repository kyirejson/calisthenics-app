## 标签照片

`POST /v1/nutrition/read-label` 接收 `{ imageDataUrl }`。使用现有服务端 DeepSeek 模型进行**视觉文字抄录**，不是专业 OCR 引擎的准确率承诺，也不是外观热量估算。

照片压缩到最长边 2048px、JPEG、编码请求小于 4MB；高细节图像，最多 1800 输出 tokens。只允许标签字段，无额外用户指令。提示词禁止猜测、混合不同营养表列、使用 NRV 百分比生成克数、将缺失字段填零；服务端校验数值/单位/枚举/字段，不能保证模型不误读数字，用户必须核对。

- 缺失蛋白质/碳水/脂肪/能量保持 `null`，在表单中为空；补齐才可保存。
- 缺失纤维保持未知，不宣称零。
- 不清楚能量单位时要求选择正确的 kJ/kcal。
- 每100mL保留体积基准，克重不自动填入。需称量这一列对应体积的实际克重或手工换算后录入；没有密度时不把 mL 当 g。
- 上线识别前明确同意联网处理；不上传姓名、训练/饮食历史。服务不保存照片、不记录请求内容；不能承诺第三方服务商不保留。
- 原图不写入个人食品或摄入记录。本机只保存核对后的数值和导入方法、模型、时间；个人上传的包装图片本身未建立永久相册。
- 关闭、切后台或切换模式取消请求；取消不能保证第三方未计费。不做定时识别或自动重试。

## 条码来源

采用 [Open Food Facts 官方 API](https://openfoodfacts.github.io/openfoodfacts-server/api/)，只读取，不上传照片或回写产品。生产查询为 `https://world.openfoodfacts.org/api/v3.6/product/{barcode}.json`。离线自动测试使用模拟数据；已对真实公开产品做少量只读联通核验，不能据此保证国内品牌覆盖率和网络可达性。

使用 v3.6 的 `nutrition.input_sets`，不再解析废弃的 `nutriments`。参考 [官方新版营养结构](https://openfoodfacts.github.io/openfoodfacts-server/dev/ref-perl-pod/ProductOpener/Nutrition.html)：

- 只取同一完整列，来源为 manufacturer 或 packaging。
- 明确保留 as_sold/prepared、100g/100ml。
- 拒绝 estimate 来源、仅计算值、`<`/`~` 等非精确修饰、缺失宏量营养、错误单位。不跨来源/列拼接纤维或其他数值。
- 制造商/包装来源标记由社区数据提供，并非本应用已经验证身份或实测认证。所有查询结果均提示核对包装。
- 校验8/12/13/14位商品码及校验位，保留前导零。不支持 UPC-E 压缩码扩展、二维码识物、条码文本通用 URL。
- 客户端不能指定 URL。服务端固定 HTTPS 地址、不跟随重定向、十秒超时、响应最多128KiB，内存缓存最多100项/24小时，缓存不等于用户食品持久化。
- 单服务额外限制14次外部查询/65秒，继承现有来源校验、请求限流、并发约束。无网络、未收录、不完整时提示转拍标签/手动录入，不编造数据。
- 网络条码查询不需要 DeepSeek 密钥，不调用 LLM。只发送条码与应用 User-Agent。

Open Food Facts 数据库使用 **ODbL-1.0**。页面保留提供方署名和原始产品链接，个人食品/记餐快照/导出保留许可、产品码、查询时间。没有批量镜像、没有将 OFF 数据伪装成 CC0、没有导入产品照片。公开上线或构建共享数据库前，需评估数据库再分发/衍生数据库许可义务，并按官方要求完成应用使用登记、配置联系信息；本次未替用户提交表单或注册服务。

## 本地试用与上线边界

```powershell
cd D:\001号仓库\calisthenics-app
npm run dev:nutrition
```

网页刷新后：今日 → 饮食 → 管理当日饮食记录 → 添加饮食记录 → 拍营养标签 / 扫商品条码。未开启相机权限仍能选择图片或手输条码。必须同意本次联网、核对标签，才能保存。

可选服务端配置：`NUTRITION_FOOD_ENVIRONMENT=staging` 使用官方测试环境（公开测试凭据 off/off）；默认 production。`NUTRITION_FOOD_USER_AGENT` 可替换为带真实联系信息的应用标识，不存客户端密钥。

`app.json` 已启用条码扫描原生插件。此前禁用条码模块的 APK 需要重新构建，不能只靠 JS 热更新补入原生能力。此次没有构建新 APK。

个人食品仍保存在本机，最多200项；导出备份包含食品与来源。清除浏览器数据/卸载会丢失，**未实现账号云同步、跨设备恢复或公共食品审核后台**。本地服务只监听回环地址，不可直接作为公网企业级 API。正式手机服务还需要 HTTPS 部署、鉴权、用户隔离、成本控制和隐私机制。
