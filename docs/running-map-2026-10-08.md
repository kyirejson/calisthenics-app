# 新跑步模块：实现与验证记录

> 此文保留 10 月 8 日的实现和测试记录。GPS 起跑限制、辅助定位订阅和长按结束已调整；当前规则见 [跑步可用性调整](running-usability-2026-10-09.md)。

日期：2026-10-08。本文记录当前工作区的新实现，不代表已向手机发布新版 APK。

## 界面与功能

“今日”顶部排列为训练、饮食、跑步。跑步页沿用已确认的深色／荧光绿模板：地图是主视图，下方依次显示里程、有效用时、平均配速、当前配速和开始／暂停／继续／结束操作。

- 地图为真实 OpenStreetMap 地图，不使用示意图冒充当前位置。只有收到 GPS 定位才显示定位点；未定位时明确提示点击定位。
- 支持拖动、缩放、回到当前位置、比例尺、GPS 精度、轨迹和每公里标记。
- Android 结束操作需长按并确认；短按不结束。辅助功能提供结束确认操作。
- 保存后可在跑步记录中展开轨迹，也可在数据页的训练历史中展开当日跑步。
- 同日多次跑步分别保存、汇总距离与次数；不混入力量训练的组数、次数统计。
- 没有心率设备、步频来源或能量测量，不填充虚构心率、步频、热量。

## 记录架构

原生 Android 模块位于 `modules/uncover-running`，通过 Expo 本地模块自动链接。它不依赖 Expo Go、Google Play Services、额外音乐／AI 服务或付费后端。

1. `RunRecorderHost` 放在页面导航之外，统筹权限、全局状态和保存，切换页面不重建记录器。
2. Android 使用用户在前台启动的 `location` 类型前台服务，及时创建常驻通知，再在独立线程订阅 `LocationManager.GPS_PROVIDER`。
3. 原生记录原始 GPS 点和基于 `SystemClock.elapsedRealtime` 的有效用时。修改系统日期不会修改有效用时；暂停期间不计时、不追加轨迹。
4. `running-journal-v2.json` 位于 App 私有文件目录，使用 `AtomicFile` 原子写入。开始、暂停、恢复、结束立即写入；运行期间每 5 秒检查点保存。
5. App 被强制终止后，读取最近检查点并恢复为暂停；保留原记录 ID、另开轨迹段，不把中断期间的时间或位移补进记录。正常运行时检查点间隔约 5 秒，最后尚未落盘的数据可能丢失；系统延迟调度或写入异常可能扩大这个窗口，不能承诺绝对不丢秒。
6. Android 与浏览器共用纯函数分析 GPS：过滤无效／低精度点、抖动、不合理跳点；暂停、中断及长时间断点不连线计距。
7. 结束后，先持久化到 App 的训练记录，再清除原生草稿。重试沿用同一 ID，避免重复记录。保存失败时保留待保存状态和重试入口。

当前精度阈值 35 米、速度异常阈值 12 米／秒、30 秒断点和移动噪声阈值均为工程过滤参数，不是人体运动的医学标准。真实里程仍受 GPS 信号、遮挡、设备精度和过滤影响，不能承诺与测绘或跑道长度完全一致。

浏览器单独使用 `navigator.geolocation`、单调时钟及本地草稿；刷新后恢复为暂停。浏览器仅承诺前台记录，不承诺锁屏、后台或页面关闭时继续定位。iOS 原生后台跑步尚未实现。

## 地图与异常处理

Android 地图瓦片在独立 IO 线程加载和解码，再由原生 Canvas 按实际屏幕密度绘制；轨迹由 SVG 叠加。这样避免 React Native 图片放入原生视图时的缩放错误，也不阻塞 GPS 回调线程。

瓦片请求使用标识 App 的 User-Agent、当前视口请求、HTTP 缓存与 ETag；没有批量下载或离线区域预取。已有真实瓦片缓存可复用；未缓存区域断网时会留空／提示重试，不能承诺完全离线地图。可见版权链接始终保留。公共瓦片服务为尽力提供，不具备可用性 SLA；地图网络失败不停止 GPS 记录。

精确定位被拒绝、系统 GPS 关闭、地图网络失败、草稿无法读取和写入失败均有明确提示，不用假坐标或假里程兜底。新增模块旧 APK 无法通过 JS 内容更新获得；旧包会提示需要新版安装包。

实现时参考了 [Android 定位前台服务说明](https://developer.android.com/develop/background-work/services/fgs/service-types)、[前台服务异常处理](https://developer.android.com/develop/background-work/services/fgs/troubleshooting)、[Expo 本地模块 API](https://docs.expo.dev/modules/module-api/) 和 [OpenStreetMap 瓦片使用规则](https://operations.osmfoundation.org/policies/tiles/)。

今日训练总览与训练历史卡片的既有浏览器回归脚本也已通过。

### Android 安装包

本地编译完成独立带 JS 的调试 APK（四种 ABI）；已安装到 Android 15／API 35 模拟器。GPS 使用模拟器注入坐标，经过真正的 Android 定位回调、前台服务、原生文件和 App SQLite 保存，不只是模拟 JS 返回值。

`scripts/smoke-running-android.cjs` 完整流程通过：

- 拒绝精确定位后 App 仍可操作；通知授权不作为 GPS 启动前提。
- 定位后启动服务，确认 `RunningService` 为前台服务。
- 暂停后原生用时和点数不增长；暂停期间移动约一公里不计入里程。
- 页面切换和锁屏时，原生 GPS 点数与有效时间继续增长。
- 关闭 GPS 后有可恢复提示，没有进程闪退；重新启用 GPS 可继续。
- 强制终止、重开后恢复为暂停，记录 ID 不变；中断期间约一公里位移不补计。
- 短按结束不保存；长按确认保存后历史、数据页都可读取。
- 跑步记录和数据页展开后，可见实际保存的独立轨迹段、里程、用时与配速。
- 数据库中只有一条同 ID 跑步记录，含独立轨迹段；清除已确认保存的原生草稿。
- 再次重启不新增重复记录；检查日志没有 `FATAL EXCEPTION`、`TypeError` 或 `ReferenceError`。

原生截图和数据库 QA 夹具保存在本机 `D:/UncoverBuildTools/temp/running-native-qa`。这些记录属于隔离模拟器测试，不是用户实际跑步。

额外将同一 Android 模拟器切换为 320×640 DP 小屏，核对开始按钮位于导航上方、地图版权可见、缩放与回定位按钮不重叠。截图复核还修正了 Yoga 布局中同时保留上下定位导致的按钮背景拉长；紧凑地图不再显示重复的中央定位提示。

为避开每秒计时刷新导致 UIAutomator 一直等待“界面空闲”的问题，使用独立测试 APK 的只读 `UiAutomation` 抓取界面。辅助工具不进入正式 App，不修改业务记录；QA 脚本拒绝对非 `emulator-*` 设备执行夹具初始化。

## 复现

```powershell
npm run check
node scripts/smoke-running-map.cjs
./scripts/build-android-ui-dump.ps1
node scripts/smoke-running-android.cjs
```

本地 Windows C++ 构建需要 ASCII 路径的快照，原仓库不移动。将当前源码复制到快照、准备相同依赖、运行 Expo prebuild、生成当前 Android JS bundle 后：

```powershell
./scripts/check-android-native.ps1 -ProjectRoot D:/UncoverBuildTools/run-map-20261008 -Target DebugApk
```

构建依赖放在隔离的 `D:/UncoverBuildTools`，不替换用户默认 Java。APK 使用本地调试签名，仅用于模拟器测试，不是已经发布、可以覆盖手机正式版的升级包。正式手机交付需用现有正式签名重新构建完整 APK，不能只推送 OTA，也不要为了安装调试包要求用户卸载旧 App。

## 交付边界与清理

用户不连接实体手机，因此没有声称已验收 OPPO 真机。尚未实测：该手机长时间户外定位、深度省电／Doze、厂商清后台策略、低存储与低电量下的持续跑步；也没有声称公共地图在所有网络永久可用。API 35 模拟器通过不等于所有 Android 版本与机型绝无问题。

已移除被替代的轨迹草图、旧地理／地图视口工具和旧跑步移除验证；原生地图图片的中间重复实现也已删除。旧跑步审计文件仅作为明确标记的历史记录，现有无关修改与用户档案不清理。

本次不发布云端构建、GitHub 新版本或手机内容更新；代码及本地验证完成后，正式安装包发布是独立步骤。
