# 浏览器定位超时核查 · 2026-10-09

## 可确认的事实

用户提供的旧版截图提示“定位暂未返回坐标，计时不受影响”。该文案仅在 `watchPosition` 返回 TIMEOUT（错误 3）时出现。这不是 35 米门槛拒绝了坐标：旧版浏览器地图预览在计距过滤之前赋值。

独立无头 Chrome 与 Edge 的只读定位测试：页面 `http://127.0.0.1:8081/`，安全上下文为 true，网页定位权限为 granted。未注入位置或读写用户浏览器档案；高精度和大致位置请求均在约 15 秒返回 `code: 3, message: Timeout expired`，没有坐标。这是独立自动化浏览器的观测，不能直接代表内置浏览器或正常交互浏览器的定位提供者行为。Windows `lfsvc` 为 Running，本机和当前用户的 location consent 均为 Allow。服务 Configuration 注册表读取被系统拒绝，未更改权限或设置，不能将其视为已排除。

因此独立浏览器测试的失败发生在获取坐标环节，不是在 App 计距环节。但内置浏览器诊断连接因环境缺少 browser-service 模块而不可用，不能冒称已读取用户当前标签的权限、网络日志或定位服务内部原因。也不能仅凭超时确定是室内、网络被阻断、Windows 未授权或设备缺 GPS。

## 代码修复

- 快速地图请求：`getCurrentPosition`、`enableHighAccuracy: false`、允许 60 秒缓存、12 秒超时；与高精度连续请求并行。
- 连续记录仍使用 `watchPosition`、高精度、无缓存、15 秒超时。大致/缓存回调仅设置地图位置，绝不累计跑步轨迹与里程，即使返回的 accuracy 小于 35 米。
- 不再丢弃错误原文。区分错误 1（访问被拒）、2（服务不能提供坐标）、3（超时）；分别标明大致和连续请求，保留原始原因，不推测未授权。
- 连续请求失败时保留已收到的大致地图位置；取消后的迟到回调无效；迟到粗略坐标或较老精确回调不覆盖较新的精确位置。重复时间戳可继续显示地图，但不重复计距。非法、过旧坐标明确提示原因。
- 没有任何浏览器位置时保留“尚无当前位置”，不增加 IP 定位服务、不猜城市、不注入虚假位置。

## 验证和交付边界

- 7 项新增定位回归通过；全量 426 项自动回归通过；严格 TypeScript 通过。
- 独立浏览器界面回归验证大致位置展示、错误码原文、拒绝位置仍计时和保存、无虚构距离；运行设置/自动暂停/恢复/保存在 320 和 390px 通过。
- 跑步地图完整回归在 320/390/607px 和短屏通过，涵盖定位拒绝、无定位起跑、弱定位恢复、暂停断段、重复保存和历史；专注页目标、倒计时取消、长按解锁及公里分段回归通过。测试坐标是合成输入，不用于宣称真实定位已恢复。
- 独立真实 Chrome 与 Edge 仍无法获取系统坐标。并行请求提高可用性，但两种请求可能共享同一提供者，不能承诺从一个没有返回坐标的提供者制造真实定位。
- 本次代码已用于本地 8081 浏览器预览，随后随 v1.7.9 发布；不包含在旧 v1.7.8 APK。正式包与升级保留数据结果见 [v1.7.9 发布核验](release-v1.7.9-2026-10-09.md)。
