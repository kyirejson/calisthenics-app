# 代码架构审核与修复报告

审核日期：2026-10-09。对象：`calisthenics-app` 当前工作区（配置版本 1.7.3），包含已提交、未提交和新增代码；不是仅审核 Git 的旧版本。

**状态更新：初次报告与第一轮结果保留用于追溯。随后用户要求解决全部剩余问题，第二轮已关闭六项债务，当前状态以 [完整整改报告](architecture-remediation-2026-10-09.md) 和 [现行架构](ARCHITECTURE.md) 为准。下文的文件行数、旧目录和延期项是审核/第一轮当时的证据，不是当前结构。**

## 结论

**确实存在代码冗余、功能移除不彻底、目录职责混用和部分页面过度集中，但不属于整个项目不可维护、需要重写的情况。** 主要问题来自多次功能调整后遗留的实现和开发工具。训练、营养、知识库、个人记忆、跑步已经有独立的业务模块；应保留这些有效边界，做局部整理。

没有发现运行时模块循环依赖。第一次把 `import type` 也算进图时出现的关联环，经排除纯类型引用后消失，不能将其当作初始化故障。没有找到较长函数体的完全一致复制；这不等于没有概念重复或近似重复。

## 审核方法与基线

- 检查 `App.tsx`、`index.ts`、`src`、两个本地原生模块、构建脚本、测试、依赖、Expo 配置和开发文档。
- 用 TypeScript AST 解析导入、动态导入、字面量 `require`、局部样式使用情况。检查运行时依赖图；从应用入口追踪可达性，同时考虑 `.web.ts` 与原生实现。
- 对不可达文件继续检查测试、生成器和打包使用情况，不能只因应用没有 import 就删除。
- 对知识库两套生成数据解析 JSON 比较，而不是仅比较文件大小。
- 基线：TypeScript 检查通过；自动发现的单元/回归测试 **378/378 通过**。
- 应用入口及源码模块共 179 个（含生成文本和旧动作静态数据）；`scripts` 根目录有 111 个文件；46 个脚本重复注册 TypeScript 测试转译器。
- 不修改源书、营养原资料、用户浏览器存储、个人记忆或现有训练/饮食/跑步记录。未连接真机，不把浏览器和单元测试描述成手机验收。

## 已核实的问题

### A1 · P1：已删除的饮食录入功能仍留下整条实现链和原生权限

证据：`src/screens/NutritionScreen.tsx` 已无手动编辑/拍照入口；`IntakeEditor.tsx`、`PhotoIntakeEditor.tsx`、`NutritionLoopCards.tsx` 没有应用消费者。`FoodCaptureCamera.tsx:3–5` 只能由这条废弃链到达，`captureClient.ts` 又保留 `/v1/nutrition/*` 识别传输。

核实的残留共 **17 个文件、118,664 字节、1,204 行**：

- `components/nutrition`：`IntakeEditor`、`FoodImportModal`、`FoodCaptureCamera`、`foodPhoto`、`PhotoFoodEditor`、`PhotoIntakeEditor`、`NutritionLoopCards`。
- `nutrition`：`captureClient`、`captureServings`、`ingredientCapture`、`mealSlot`、`servings`、`sourceURL`。
- `nutrition/capture`：`food-import`、`photoPrompt`、`transport`、`validation`。

`package.json` 与 `app.json` 仍带相机、图库、图片处理依赖、插件和 CAMERA 权限。它们的源码使用方全部属于上述废弃链。四个相机/标签浏览器 smoke 脚本仍点击已经不存在的按钮；部分单元测试甚至要求废弃插件存在，因此“测试通过”没有证明功能清理完成。

影响：维护者误以为功能还在；下次重新构建继续携带不需要的原生模块和权限；旧测试妨碍正确清理。**不可据此声称它们已被 Metro 放进当前运行的 JS 包，或就是此前闪退原因。**

修复：删除确认废弃的 UI/识别链、旧相机 smoke、相关依赖和权限；替换仅测试废弃服务的断言。保留 `engine`、`journal`、`vision`、`foodImport`、`photoStorage`、`photoMetadata`、展示组件及历史数据兼容测试。保留现有日记写入接口，不在本轮增加 Agent 饮食能力。

### A2 · P1：知识库生成两份相同正文，存在两套种子入口

证据：`scripts/import-knowledge-vault.mjs:42–45` 把全部资料写入 `private/bundle.ts`，又把授权资料写入 `referenceBundle.ts`；`prepare-public-resources.cjs` 仅在私有文件缺失时生成公开种子转导出。两种环境的初始化数据来源因此不同。

当前两个文件分别约 2.05 MB，解析后的 JSON **完全一致**，均包含营养 48 篇、囚徒健身 69 篇。两份内容的差别只有生成注释。应用存储通过 `private/bundle` 读取；公共构建排除私有目录，再由安装脚本补转导出。

影响：本地和云构建易发生内容漂移；同一正文占用两份源码，增加维护成本。**不是已证实的 APK 双份加载问题。**

修复：公开正文只保留一份；私有种子只引用公开正文并追加真正的私有库。提取统一种子生成器，覆盖空库、额外私人库、重复 ID、未知资料不被公开和内容校验测试。保留已授权的两套全文，以及“只补缺失库，不覆盖用户笔记”的存储行为。

### A3 · P2：今日页同时负责分页导航和完整训练计划交互

证据：`TodayScreen.tsx` 审核时 455 行、39,495 字节、27 个 import。一个文件里有训练/饮食/跑步分页、跑步恢复、训练处方、日历、倒立条件、减重计划配置、计划生成进度、多个弹窗和样式。`Props.onNutrition` 在 `TrainingTodayScreen` 中未消费，仍在 `App.tsx` 和页间传递。

影响：修改导航也要理解训练计划 UI；无用回调让真实职责不清晰；之后统一 UI 容易修改错分支。

修复：保留 `TodayScreen` 为分页/外壳，把完整训练页移到 `TodayTrainingScreen`；按使用方分离局部样式，移除无消费者回调。处方规则、操作顺序、更新阻塞、默认页、日历和 GPS 恢复逻辑不改。

### A4 · P2：目录名与职责不符，开发工具和运行时代码边界含糊

证据：`server/book-knowledge.mjs`、`server/prisoner-knowledge.mjs` 被 `scripts/check-book-knowledge.mjs` 和测试使用，当前应用从 `src/knowledge` 读取资料，没有 HTTP 服务入口。`test-all.cjs` 却仍按 server 目录运行语法检查。`src/data` 同时装静态动作数据与处方/日程/统计逻辑。

影响：容易误判必须部署服务端；新模块不清楚应该放哪里。历史研究脚本与可运行构建工具混放，入口也难辨认。

修复：将 Node 知识索引工具移到 `scripts/lib/knowledge`，更新调用者和语法检查；已有私有索引路径保留兼容，不搬走或删除资料。增加目录职责说明。`src/data` 全量迁移涉及大量调用者，先写清边界，后续按功能逐步迁移，避免本轮机械改名制造大面积冲突。

### A5 · P2：测试转译注册重复，结构测试绑定页面文件名

证据：46 个脚本各自实现 `require.extensions['.ts']` 转译，ES2020/ES2022 与 JSX 参数写法不同；今日页测试直接读 `TodayScreen.tsx` 检查子功能。旧相机 smoke 还检查删除的入口。

影响：修一个测试加载问题要改多处；合理拆分页面也会把测试打坏；旧测试文件容易被误当成当前验收项。

修复：建立共享 TypeScript 注册器，保留各脚本原转译选项；结构断言指向真正的职责模块。增设运行时依赖环、残留旧功能、种子组织和页面职责的自动检查。浏览器脚本使用隔离数据，不读写用户真实会话。

### A6 · P2：开发文档描述的是过期产品，缺少当前架构入口

证据：`README.md` 首页仍为 v1.6.0，并宣称 585 项测试、相机识别、私人助手原生入口、公开知识库尚未准备好。实际配置为 1.7.3、基线 378 项，助手/相机入口已变更，两套文字知识库已随包生成。`docs/PRODUCT-DECISIONS.md` 混有旧营养预置/旧训练决策，不应被当作现状说明。

影响：按 README 开发或发版会理解错依赖、功能和资料分发边界。

修复：README 改为当前实现与真实验证范围；建立当前架构文档和脚本分类入口。给历史决策文档加明确历史标记，不覆盖用户的研究内容，也不在本轮重新审核运动/营养研究。

### A7 · P3：移除旧个人档案/记餐界面后保留了局部废弃样式

证据：`ProfileScreen.tsx:115–117` 中旧表单、弹窗和性别选项样式已经没有使用；`NutritionScreen.tsx:175` 的 `recordActions`、`textAction` 未消费。

修复：只删局部确认未用样式。`MovementDetail` 和 `todayTrainingStyles` 的导出样式被其他组件消费，`ui.tsx` 还有动态样式键，不能按单文件扫描结果误删。

## 第一轮曾延期的债务（第二轮已全部关闭）

1. `AppStore.tsx` 约 343 行，承担多个域的加载、迁移和写入；同一个 Context 的变化会通知所有消费者。本轮不随意拆掉跨域队列或重置流程，以免引入丢数据。后续若性能测量表明存在问题，应按域拆 selector/context，同时保留统一事务协调。
2. `DataScreen`、`ProgressScreen`、`TrainingScreen` 和聊天 UI 仍包含较多交互逻辑；压在长行里的 JSX 使行数低估了复杂度。应根据测试边界拆图表/记录/交互，不为满足行数指标强行切文件。
3. `src/data` 作为历史名称仍包含训练领域算法；全量搬到 `domain/training` 属后续分步迁移，不是假装本轮全部解决。
4. 大型知识文本可以进一步优化懒加载/检索索引，但没有启动时间、内存或真机性能实测，本轮不宣称全文导入导致卡顿。
5. `server/private` 中既有离线索引作为兼容构建资料保留；移动开发工具不等于删除索引或增加服务端需求。
6. 当前知识库种子只初始化缺失库，已有库不因新版安装包自动覆盖。这保护用户笔记，但以后更新预置资料需要独立的版本/冲突策略；不能把“修改种子”宣称为“所有已安装资料都已刷新”。本轮不改变这个数据保护行为。

## 执行顺序与验收

本报告先形成，再开始改代码：A1 → A2/A4 → A3/A5/A7 → A6 → 回归验证。

验收：TypeScript、全量有效测试、种子内容和原文哈希、运行时架构检查、页面多尺寸浏览器回归，以及 Android JS 打包/原生配置检查。测试数量因废弃功能退场会变化，不将新增数量当作质量证明。此次不上传、不发版、不更新手机二进制。
