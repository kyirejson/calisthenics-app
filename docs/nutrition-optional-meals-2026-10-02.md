# 餐次选填与助手长回复（开发版，2026-10-02）

## 行为

- 早餐、午餐、晚餐、加餐是记录分类，不是必须填写的四项任务。用户可只记录一餐，其他餐保持未知。
- 每餐可选“记餐”“没吃”“撤销状态”。“没吃”单独持久化，不创建零热量食品、不删除已有食品；与实际记录冲突时要求先核对。
- 明确的当日表达（例如“早餐，我没吃”）可生成餐次状态操作。默认确认后写入，完全访问模式直接写入；问题、计划、习惯、其他人的情况和混合表达不能直接执行。
- 操作仍经过权限、数据版本、重复执行回执和持久化校验。保存失败不会声称已完成，状态可撤销。
- 调整推荐不再强制补齐之前的餐次。记录不足时按原推荐与偏好调整，不把未记录当作没吃，不编造热量缺口。
- 全天记录完整的确认和复盘仍是选用功能；餐次选填不自动变成“全天已记完”。

## 回复长度

已移除提示词、服务端结果校验、客户端和本地对话归档中的 50 字限制。回复按问题需要完整表达。保留 8000 字符的传输异常保护和有限模型输出预算，不代表要求回复写满；超大异常响应不执行工具。

完整回复留在本机归档，发给模型的近期历史按成对问答压缩到原有请求预算，避免长回复使下一轮请求失效。

## 范围

本次未重做全天自由餐次规划器：推荐菜单仍使用原有四类模板，但实际记录与调整入口不强制四餐。未发布新 APK 或公网后端；本地开发服务已加载新代码。真机语音与输入法适配仍须 OPPO 设备验证。

530 项自动回归通过，TypeScript 检查通过。覆盖未记录与没吃的区分、保存与撤销、已有食品冲突、权限确认、回执重放、数据变化、保存失败回滚、长回复与后续对话预算。
