# MAX 更名与语音连续播放优化

日期：2026-10-16。本文记录本轮源码变化；不是已发布 APK 的更新公告。

## 语音为什么会像分两段说

代码中存在两处能造成不自然停顿的因素：

1. 合成文本在 40 字窗口或句号处拆段，长句可能在语义未结束时被硬切。
2. 合成端虽然已经提前准备了后续音频，但渲染端仍逐段调用播放器，等前一段播放头完全走完才取下一段。前一段耗尽后才继续写入，会增加流式 AudioTrack 欠载和重新达到起播阈值的机会。

原实现已经复用同一条流式 AudioTrack，不是“每句话都重新创建播放器”。本轮修改针对的是音频供给边界。Android 文档也明确说明流式数据补充不及时可能导致欠载与音频异常，欠载后还涉及起播阈值。[AudioTrack 官方说明](https://developer.android.com/reference/android/media/AudioTrack)

这些是代码核实的风险点，不冒称已经获取用户手机录音并定位到某一次听感故障。

## 已改动

- 一个回答只调用一次连续渲染循环。已准备好的下一段在前段耗尽前续入；维持有界的预写入，不等待整个回答合成完。
- 每段合成窗口调整为 64 字；较长句优先在窗口内逗号、分句或英文单词边界拆分，保留闭合引号和 Unicode 字符。没有裁剪模型原文、强制缩短回答或加速朗读。
- 新增纯播放时间轴，按实际播放头推进原文范围和已读位置；提前合成、排队及补齐起播所用的静音不计为“已朗读”。
- 保留真实缺音频时的 buffering、暂停恢复、消费停滞检查、取消代次、FIFO 错误收尾与现有合成重试。正常在播放时不因后段仍在合成而报超时。
- AEC 仍使用实际送入播放器的波形和时钟，保留播放尾音保护；没有放宽 VAD / 打断阈值，也没有以禁用用户打断来掩盖问题。
- 移除旧的逐段播放入口及重复私有 Packet 类型；生产不保留两套渲染路径。

主要文件：`VoicePcmPlayer.kt`、`VoicePlaybackTimeline.kt`、`VoiceSpeaker.kt`、`VoiceSpeechChunks.kt`。

## MAX 身份与唤醒词

- 聊天标题、助手消息署名、欢迎页、语音设置、待机提示、Android 通知与系统助手标签改为 MAX。
- 文字与语音共用独立身份说明：MAX 是助手名称；DeepSeek 只是当前模型 API 提供方。模型连接、密钥错误及数据发送说明仍如实披露 DeepSeek，不把模型伪称自研。
- 实际 KWS 词表为英文 Max 与 Hey Max，使用官方模型词典中的 `M AE1 K S` 发音；资源清单同步校验词表字节和 SHA-256。不是仅改界面文字。
- 原来的提供方命名聊天组件已迁移为 `AgentChat` / `AgentChatHost`，旧文件不作为兼容副本保留。
- Android 已选择的组件 ID、通知 channel ID、本机偏好存储键和模型资源目录等稳定标识保留，避免更名导致授权、设置或默认助手失效。这些内部标识不作为对用户展示的名称。
- 30 秒无活动回待机和由模型选择 `end_voice_conversation` 的逻辑保留；语义退出不靠关键词匹配，不关闭全局唤醒、不清除上下文，也不停止音乐或跑步。详见同日待机设计记录。

### 唤醒检查的边界

离线 Max 文件如果从第一个特征帧立即发声，初始探针未检出；加入模拟待机环境的 200 毫秒前置静音后检出。Hey Max 在两种情况下均可检出。测试脚本明确保留前置静音条件，而不是降低门槛来取得通过。

正样本是 Windows 合成声音，不是真人。额外使用内置 Melo 生成的两个英文呼唤样本没有检出，不能以两个正样本宣称任意音色或口音均已验收。这里没有声纹认证，也没有录制用户声音；最终真人发音、麦克风和 ColorOS 后台唤醒仍需要真机体验反馈。

## 交付边界

本轮没有更换 TTS 模型、增加云服务或扩展手机控制授权；也没有打包上传正式版本。原生播放和词表变化需要重新构建 APK，已发布 v1.7.22 不会自动获得源码修改。

模拟器测试能验证执行路径、PCM 消费和事件顺序，不能证明 OPPO 外放环境下所有音频延迟、口音召回及主观听感均达到商用实时语音产品水平。
