## 1. 设计哲学：两条主轴，一个主语

原著的记录观（第一册第十一章"金科玉律"）三条原则直接成为设计宪法：

1. **"记忆不可靠，白纸黑字才可信"** → 历史页是 App 的地基，数据一旦记录永不丢失（不锁时间深度）。
2. **"进步，就是超越你在过去的成就"** → 一切对比只和自己比：与上次比、与上月比，不做排行榜。
3. **"记录应该快速、有效。拖沓繁冗就坚持不下去"** → 曲线自动派生，用户零额外录入。

**一句话主语**：曲线的主语是动作，不是肌肉。不画 1RM 估算、不画容量吨位、不画肌群疲劳评分——这些是杠铃世界的语言，原著的主语是"动作质量 × 难度等级"的推进。

**两条主轴曲线**（贯穿四册的唯一进度度量）：
- **动作等级线**：每个系列"当前第几式"随时间的推进（阶梯图，升级事件打点）。
- **当前式成绩线**：动态类动作 = 最好一课的全组次数（如 3×12 → 3×14）；静态类动作 = 最长完美保持秒数（如 45s → 60s）。

**辅轴**：出勤（周 streak，非日 streak）、自由评注、节点体重+照片。

**行业差异化空白**（对标确认无人做，是本方案的机会）：① 静态保持（hold）秒数曲线；② 次数×体重比曲线（体重线与次数线同图反相关）；③ 技能解锁时间线（"2025.3 上斜引体 → 2025.9 标准引体"的横向时间轴，比百分比更可分享）。

## 2. 现状数据盘点与缺口

### 2.1 已有（可直接派生曲线）

| 数据 | 字段 | 位置 |
|---|---|---|
| 训练会话 | `TrainingSession`：workoutId/workoutName/startedAt/completedAt/durationSeconds/quality(solid·hard·pain)/completion(complete·partial)/kind | types.ts |
| 每组记录 | `SessionExercise.sets[]`：{reps, completed, unit: reps·seconds·steps·meters} + targetSnapshot | types.ts |
| 体重 | `Profile.weightHistory[]`：{date, kg}（当前仅减肥控重入口） | types.ts + weightTrend.ts |
| 进阶状态 | 各系列当前式数、专项验收通过次数 | progression.ts |
| 跑步 | distanceKm / calories / durationSeconds | TrainingSession |

### 2.2 缺口（需新增记录）

| 缺口 | 说明 | 方案 |
|---|---|---|
| **升级事件表** | 现在升级直接改 levels，无时间戳——等级阶梯图无法回溯 | 新增 `upgradeEvents: {id, date, series, fromLevel, toLevel, standard, source:'验收'\|'手动设阶'}[]` |
| **动作级最好成绩聚合** | 每式"最佳一课"需从 sessions 派生聚合 | 派生函数 `deriveExerciseBest(exerciseId, sessions)`，不落库 |
| **巩固训练记录** | 巩固日（P1 功能）的记录类型不存在 | 新增 `greaseLog: {date, slot:'晨'\|'午'\|'晚', attempts, quality}[]` |
| **体重入口统一** | 体重记录目前只在减肥控重的营养页；力量体重比需要体重序列 | 体重卡提升为数据页通用组件（所有目标可记录，P1） |
| **训练评注** | 原著评注是排难解忧的信号采集，现在无法备注 | 训练完成反馈弹窗加可选一行评注（≤100 字） |

## 4. 页面设计规格

### 4.1 训练历史页（列表模式 A + 日历模式 B）

**列表流**（默认）：按月分组的倒序卡片流，月份 sticky 头 + 年份快跳。
每张记录卡字段：`课程名（六艺 B · 拉力与下肢）｜ 日期 ｜ 时长 ｜ 完成度徽章 ｜ 质量反馈点（柠檬/橙/红三色点）｜ 当次最好成绩（如 引体 3×12）`。跑步卡显示距离/配速。

**会话详情页**（核心，全 App 共通）：
- 每组一行："组号 ｜ 动作 ｜ 目标 vs 实际（3×10 → 3×12）"，与**上次同动作逐组对比**（↑ 多 2 次，绿色；↓ 红色；= 灰色）——Hevy 拉开差距的功能，自重版用次数/秒数替代重量。
- 顶部摘要：时长、完成组数/总组数、质量反馈、当次总次数。
- PR 高亮：本课打破该动作最好成绩时，行尾柠檬绿星标 + "新纪录"。
- 评注行（P0 后期）：可选自由文本。

**日历视图**：月视图蓝点=完成训练、空心点=部分完成、柠檬点=当天发生技能升级；可切换"年视图"整年缩略；点有记录的日期直达当日会话。**Streak 规则照抄 Hevy：按"周"计（连续每周≥计划次数），当周补练可续，不因"额外休息一天"归零**——这正是原著"别受一周七天人为概念限制"的弹性。

### 4.2 进步曲线页（Progress）

**结构**：动作选择器（当前主训动作默认选中）→ 主图 → 指标切换 → 时间范围（1M/3M/6M/1Y/All 分段控件）。

| 图表 | 类型 | 回答的问题 | 数据来源 |
|---|---|---|---|
| ① 次数曲线 | 折线，Y=该式最好一课的总完成次数（或 3×12 的"末组次数"） | "我的俯卧撑变强了吗" | sessions 派生 |
| ② 保持秒数曲线 | 折线，Y=最长完美保持秒数（静态类主图） | "靠墙顶立从 30s 到 60s 了吗" | sets(unit=seconds) 派生，**市场空白** |
| ③ 等级阶梯图 | 阶梯折线，Y=系列当前式数，升级点打柠檬绿标记 | "我在旅程的哪一步" | upgradeEvents 表 |
| ④ 次数 × 体重比 | 双线同图：次数线（主）+ 体重线（辅，灰）反相关；或单线"总负荷/体重" | "次数没涨是因为体重涨了" | sessions + weightHistory |
| ⑤ 周训练频率 | 柱状图，Y=每周完成课数，叠加目标线 | "我坚持住了吗" | sessions 派生 |
| ⑥ 跑步曲线 | 距离/配速折线 | 跑步进步 | running sessions |

**交互细节（照抄 Strong/Hevy 验证过的）**：
- 单点触发出 tooltip：日期 + 数值 + 当日组次详情；**双击数据点跳转该日会话详情**（历史与进步互通闭环）。
- 每条曲线下方固定一张 **PR 卡**：该动作历史最佳（最多次数/最长保持/最早日期），**点 PR 直达创造纪录的那次训练**。
- **空/少数据**：少于 3 条记录不画趋势线，只画散点；新用户首屏展示"本周 vs 上周"小对比卡 + "再记录 N 次解锁完整曲线"引导，禁用回归线。
- **平台期呈现**（抄 Stronglifts 叙事）：连续 4 周数值持平自动标注"巩固期"，文案"保持=进步——体重下降期的力量维持同样是变强"，并引导去等级阶梯图看长线。

### 4.3 里程碑时间线（差异化主打）

横向滚动卡片流，每张卡 = 一次升级事件：
```
┌──────────────┐
│ 🏆 第 4 式 · 半俯卧撑        │
│ 2026-08-14 · 通过专项验收   │
│ 用时 43 天 · 距上一级 ↓3 个月 │
└──────────────┘
```
- 依赖 §2.2 的 upgradeEvents 表；历史数据可从当前 levels 反推一条"起点事件"。
- P1 起支持分享卡（成绩 + 等级 + streak 合成图）。

### 4.4 周报 / 月报

- **周报**（每周一送达"我的/数据"页顶部 + 可选推送）：本周完成课数/时长/总次数、与上周环比 ↑↓%、当前周 streak、验收进度变化、下周重点（原著话术）。
- **月报**（每月 1 日生成，卡片流，支持生成分享海报）：训练次数/容量/组数/PR 数/活跃天，每卡一指标一箭头（Hevy 月报模式）；年报版"Year in Calisthenics"（最佳月份、解锁最多的系列、首成动作）。

## 5. 视觉规范（UI 设计师视角）

1. **颜色语义**：曲线主色 = 墨色（`#151712`）；当前值点与"新纪录"标记 = 柠檬绿（`#C8F04D`）；升级事件 = 柠檬绿实心菱形；对比箭头：好=绿 `#228B5A`、差=红 `#D84A3A`、平=灰。**同一指标全 App 一种颜色**。
2. **图表容器**：沿用纸色内容 + 白卡 + 细线边框；深色总览卡沿用 hero 模式；网格线用 8-12% 墨色，不加横纵网格以外的装饰。
3. **克制原则**：默认每动作只露一张主图（动态=次数，静态=秒数），其余指标进"切换 tab"；总览首屏卡片 ≤4 张。
4. **空状态**：0-2 条数据时展示插画式引导卡（"完成第一次训练，你的曲线从这里开始"），不渲染任何会误导的"陡峭趋势线"。
5. **字体层级**：大数字（streak/容量）用 900 字重 32pt，坐标轴标签 10-11pt 500 字重，与现有标题系统一致。

## 6. 技术实现方案

1. **图表库**：`victory-native XL`（Skia GPU 渲染，大数据量+动画）或 `react-native-graph`（BlueSky 在用，纯折线最优）。禁用 SVG 基础库画长曲线（几千点会卡）。
2. **性能**：曲线数据 LTTB 下采样（>300 点时）；历史列表 FlatList 虚拟化 + 按月分页查询；聚合函数（deriveExerciseBest 等）用 useMemo 缓存，必要时预计算落库。
3. **数据口径**：
   - 最好一课 = 该 exerciseId 在单次会话内"全组达标"的最高记录；无全组达标时取末组最大值并标注。
   - 保持秒数 = unit='seconds' 的 completed 组最大 reps 值（字段复用 reps 存秒数）。
   - 体重取当日最近一次记录；无当日记录时取前向最近值（7 天内有效）。
4. **深色模式**：图表色值用语义 token 注入绘制层（Skia 不吃 CSS 变量），预留 dark token。
5. **通知/推送不在本期**（P2），周报先做页内卡片。

## 8. 红线与避坑（合并原著禁项 + 行业教训）

| 红线 | 出处 |
|---|---|
| 不画 1RM 估算、容量吨位、肌群疲劳评分 | 原著："不要执著于数字，你的身体并不理解数字" |
| 爆发力课程不出现"次数进度条"，改 PARC 四要素 + "10 试 9 成"记录 | 三册 10/12 章 |
| 不做断签归零惩罚，streak 按周计、允许补练 | 原著弹性 + Hevy 验证 |
| 不锁历史时间深度（付费墙锁图表种类，不锁时间） | Hevy/Strava 教训 |
| 不做公开排行榜与默认社交分享 | 原著保密原则（"公开立 flag 耗尽精神力量"） |
| 不画无数据趋势线、不用彩虹图表 | 行业避坑 |
| 不做"连续打卡X天奖励"式游戏化焦虑 | 原著"智者之道"：存次数，不凑数 |

## 9. 一句话总结

**历史页是"做自己的教练"的账本（原著金科玉律的数字化），进步曲线的主语是动作、刻度是等级与秒数——先用现有会话数据零成本画出次数/秒数两条主轴曲线和周 streak 日历（V1），再用升级事件表点亮技能解锁时间线（V1.5），让"今天没练"的用户明天有理由回来。**
