## 数据与业务逻辑

| 问题 | 当前处理 | 验证 |
| --- | --- | --- |
| 档案迁移失败导致后续记录不加载，新记录覆盖旧历史 | 五类数据独立读取；失败域暂停写入，其余继续加载；迁移失败仍展示已解析数据 | 模拟迁移写失败、读取失败、五类损坏、训练历史追加 |
| 全档案快照覆盖队列内其他修改 | saveProfile 仅用于初次建档；编辑使用 patchProfile；数组、等级等合并基于队列内最新档案 | 并发修改体重/姓名/两个动作等级均保留；旧快照拒绝 |
| 加载失败后无恢复入口 | 提供恢复导出和重新读取；无档案时不进入会覆盖坏数据的建档流程 | 五类损坏浏览器场景均保留原文并成功重试 |
| 重试读取与已接受写入竞争 | 重试先关闭新写入窗口，排空既有队列，再重新加载；阻止同时清除 | 阻塞写入、重试、晚到写入及清除竞争测试 |
| “不过敏”被识别成过敏 | 否定或更正不生成过敏记忆，不调用模型执行记忆建议；旧否定记忆不参与过敏合并 | 肯定/否定意图和接口回归 |
| 过敏记忆与营养档案创建顺序影响过滤 | 手动过敏原与记忆来源分离；每次修改和重启统一重算有效限制 | 两种创建顺序、重启、删除记忆、同名手动限制保留 |
| 切换训练专题改写营养目标 | 专题切换只恢复训练配置，不改独立营养目标 | 器械→街头→器械后仍为原增肌目标 |
| 编辑器未保护热更新 | 器械编辑、今日配置、档案编辑及进阶保存占用更新保护 | 更新锁获取/独立释放、页面调用与浏览器编辑流程 |
| 私人索引缺失却看起来可用 | 可配置私有索引目录或压缩文件；严格结构校验；health 区分 unconfigured/degraded/ready；助手显示缺库提示 | 囚徒索引缺失、损坏、重复编号、压缩解码、完整状态和严格启动校验 |

旧饮食数据没有过敏来源标记时，已有设置保守视为手动限制，不能凭猜测自动删除。用户可在营养设置中核对。JSON 恢复导出不含照片，也没有新增自动导入/自动修复任意坏文件功能。

## 上线边界

本轮没有更新公网后端或 App 发布版本。Render 的知识库需要有权限使用的私人索引通过部署侧私有文件目录提供，不能把书籍原文提交 Git 来“修复缺库”。

部署配置及就绪语义见 nutrition-service.md 的“知识库就绪与部署”：
NUTRITION_KNOWLEDGE_DIR 指定私有目录，或 NUTRITION_PRISONER_INDEX 指定囚徒压缩索引；npm run knowledge:check 缺索引时返回非零；NUTRITION_REQUIRE_BOOK_KNOWLEDGE=true 可要求囚徒索引完整才启动。

health.ready 仅验证密钥已配置和索引结构完整，不代表真实密钥、模型能力或回答正确性已经线上验收。本轮也不宣称代码中不存在任何尚未发现的问题。
