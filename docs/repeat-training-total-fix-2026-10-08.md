# 再练一次：当日总量显示修复

## 复现与原因

通过隔离浏览器中的真实“再练一次”按钮完成同一天同一课程两遍：首遍该动作四组各 9 次（36 次），第二遍四组各 6 次（24 次）。存储有两条不同 ID 的训练，历史聚合可以得到 60 次；并非覆盖了首次训练。

数据页被路由卸载后，会把动作系列、阶数、指标、时间范围重新初始化。其中指标重新变成“单组最佳”，动作系列重新变成俯卧撑，使返回后的数字不是刚才查看的同动作当日总量。

## 修改

- 将曲线查看选项提升到 AppShell，退出数据页去再练，再回来仍保持相同动作、阶数、指标和范围。
- 首次默认查看“当日总量”；用户主动选择“单组最佳”后仍尊重其选择。这里只调整查看选项，不修改训练计划。
- 训练历史的日图表卡片显示每项动作的累计实际数量；不同动作、单位、每侧约定及设备重量口径继续分开。后续卡片布局与默认收起行为见 `training-history-chart-cards-2026-10-08.md`。
- 不改动已有训练，不重置当天，不重复计入同 ID 的暂存版本。

查看选项在本次 App 运行期间保留；重新加载 App 使用默认查看选项。训练记录仍持久化在本机，重新加载后总量仍可按真实记录重算。

## 验证

- `smoke-repeat-training.cjs` 使用真实按钮操作：36 + 24 = 60；第三次仅记录一组 5 次后为 65；删除第三条后回到 60；刷新后两条原记录及总量保留。
- 点击再练但尚未完成组时不会增加训练量，也不会清掉原记录。
- 新增三项回归测试覆盖叠加 / 单组最佳口径、部分记录 / 同 ID 版本 / 删除重算，以及查看选项的路由生命周期。
- 检查在独立浏览器上下文执行，不修改用户浏览器中的真实训练数据。
- 最终 TypeScript 检查与 344 项自动测试通过，完整图表浏览器回归通过（含布局、触摸滑动及刷新后记录保留）。
