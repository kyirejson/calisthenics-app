# Android 营养助手：数据库与语音输入修复

## 证据与边界

用户的 OPPO 截图显示助手回答已返回，随后出现 `NativeDatabase.closeAsync` / `unable to close due to unfinalized statements or unfinished backups`。

项目所用 Expo SQLite 的 `withExclusiveTransactionAsync` 会打开临时连接，并在 `finally` 关闭该连接。对话归档的迁移与逐条保存均曾使用这个入口，符合截图的报错路径。截图证明保存链路报错，不足以证明所有原生闪退均由它引起。

用户选择暂不连接手机，因此本次没有读取手机日志，也没有真机验证。未卸载、重置或删除任何用户记录；未重新发布 APK 或 OTA。

## 数据库修复

- 保持原数据库文件、表、FTS 索引和迁移标记，不清除、不重建用户历史。
- 归档生命周期内持有一个独立连接，不再逐条创建和关闭临时事务连接。
- 所有读写共享串行队列；写入与索引更新在同一连接的 `BEGIN IMMEDIATE` / `COMMIT` 事务中执行。
- 写入失败回滚后允许重试；回滚失败则阻止继续使用状态不明的连接，并提示重开 App，而不是吞掉错误或清空数据库。
- 浏览器的 IndexedDB 实现不变。

## 语音修复

- 替换旧的散落监听代码，集中管理准备、收音、整理和空闲状态。
- 准备阶段可取消；语音活动期间禁用文字编辑与发送，结果仅进入输入框，核对后再发送。
- 区分 iOS 的累计文本与 Android/Web 的分段文本，保留已完成片段并替换当前临时结果，不推测或改写食物数量。
- 使用普通话和有限的公开食物词提示，不将个人档案或历史聊天用作语音词表。
- Android 继续使用系统默认识别服务的原生麦克风路径，不强行指定 Google 服务、不强制离线模型，也不增加第三方付费识别服务。
- 请求 4 秒静音结束间隔；启动、收音、结束有超时上限，且不自动重启录音。
- 权限、网络、无语音、麦克风占用、语音服务缺失分别提示；取消、关闭、切后台后旧回调不能修改输入。
- 不持久保存音频。权限弹窗引起短暂失活不直接取消，但回到后台后不会开始录音。
- 修正 Android 助手标题的状态栏避让。

词表和静音参数是否生效取决于系统识别器，不能由本次代码测试保证 OPPO 的实际识别准确率。Android 官方文档说明部分识别参数可被服务忽略：[RecognizerIntent](https://developer.android.com/reference/android/speech/RecognizerIntent)。各平台的分段、连续录音和词表能力参见 [expo-speech-recognition](https://github.com/jamsch/expo-speech-recognition)。

## 验证

- TypeScript 检查通过。
- 全量 505 项自动测试通过；新增 3 项数据库事务测试、9 项语音会话测试。
- 数据库测试使用真实 Node SQLite/FTS5，并让旧的临时连接事务入口直接报错，验证新实现不依赖该入口。
- 浏览器测试使用独立数据与模拟语音/模型，不操作用户标签页、麦克风或付费服务。
- 营养助手浏览器回归在 320 / 390 / 650 / 1280 像素宽度全部通过；包括临时识别文本替换、语音期间禁止发送、权限拒绝后恢复编辑、确认记餐和重开历史。
- Harness V2 浏览器回归在 320 / 390 像素宽度通过；包括 140 条历史检索、问卷档案、权限模式、记忆删除和未知食品拒绝记录。
- 实际 OPPO 崩溃栈、系统语音服务兼容性和更新安装后的结果仍待真机复测。

## 手机复测

获得包含本次修复的新安装包或兼容的正式更新后，保留现有数据覆盖更新，不先卸载：

1. 发送普通文字，再连续发送几轮，确认无数据库错误且重开助手后历史仍在。
2. 说包含多个食物和份量的句子，核对文字，结束录音后发送，再确认饮食记录。
3. 测试拒绝麦克风权限、取消准备、结束录音和切后台，确认均能回到可编辑状态。
4. 若仍出现进程闪退，再读取仅属于该 App 的错误日志，不能把界面报错当成全部崩溃原因。
