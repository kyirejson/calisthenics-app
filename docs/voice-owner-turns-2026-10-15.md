# BLACK 主人验证与连续语音轮次重构

实现纳入 v1.7.17。下文记录开发环境的验证结果，不代表用户 ColorOS 手机已经完成验收。

## 交互顺序

1. 单麦克风采集，保留实际 PCM 播放参考，运行本地 AEC3 与回声相干性处理。
2. Silero 只产生疑似人声候选，不直接取消回答。
3. CAM++ 验证登记的主人：BLACK 取神经关键词时间戳对应的音频，与个人唤醒模板比较；后续语音按独立音频包重新验证。上一包通过不授权下一包，不能用旧主人人声填充新的短音节。
4. 主人候选先暂停播放，保留 PCM 位置及原请求，转写片段累计到同一草稿。
5. 只读判定调用根据完整上下文选择 respond / wait / ignore。wait 等待新增发言，不反复请求相同草稿；ignore 恢复播报；respond 才取消旧请求并进入原有 Agent 和全部授权工具。
6. 单独且经过个人声纹验证的 BLACK 直接进入原 Agent，省去额外的轮次判定调用；由原模型回答一次，不增加本地“我在”。普通发言仍由只读判定决定是否回应。
7. 模型文字流进入同一聊天记录，最终回答由系统 TTS 合成文件、统一 PCM 播放。长回答结束后重新计算继续倾听窗口，不清除用户可能已经说出的下一句话。

识别器的 650 ms 分段和 800 ms 候选等待不是用户轮次结束规则，只用于产生候选，不能授权写入。只有新增的已验证主人人声使旧判定失效；未知人声可以暂缓应用结果，但不撤销它、不额外请求模型。被拒绝的旁人尾音不进入 ASR，也不删除之前已经验证的本人文字。网络/格式错误不降级为执行，判定失败只重试一次只读判断，首次唤醒后的等待/失败也会在 20 秒主人静默后恢复待机。

## 主人声纹与隐私

- 在服务设置关闭监听后主动登记；需手机解锁、App 前台、安静环境。
- 朗读三段不同内容，每段以 BLACK 开头，至少收集 3.2 秒有效人声，读完停顿后才推进下一段；最后再单独喊一次 BLACK，使用这次未参与建库的音频验证短唤醒，失败不保存。三段一致性检查、短片段模板、关键词模板各有职责，不能把一致性当作未来识别准确率。
- [模型作者说明](https://www.modelscope.cn/models/iic/speech_campplus_sv_zh-cn_16k-common)公开建议余弦阈值 0.31；当前长语音使用至少两个样本支持的 0.40 工作点；短语音与三组 320/640 ms 模板比较，前两组均值至少 0.43、第二组至少 0.40、第三组至少 0.35。BLACK 使用三次个人关键词模板，前两次均值至少 0.60、第二次至少 0.55。这些是当前工程工作点，**不是经用户群校准的误识率保证**。
- 通用音频包通常收集 640 ms 有效人声开始比对；不确定时继续收集，最多到 1280 ms 后拒绝。最终短片段不足 320 ms 不以旧主人人声补足；极短口令可能因此无法识别。专用 BLACK 路径要求至少 192 ms 有效人声及独立回读通过，不能据此声称所有短词均已可靠识别。
- 使用 SHA-256 固定的公开 CAM++ 中文 16 kHz ONNX 模型，许可与来源在 APK 内 SPEAKER-NOTICE.txt；不申请云账户或火山服务。
- schema 2 保存三个长语音特征、每段最多 12 个短片段特征和三个 BLACK 特征及模型版本；Android Keystore AES-GCM 加密，位于 noBackupFilesDir。原始登记音频不落盘、不上传；公开模型与个人声纹分开。旧开发版登记需要重新完成回读，没有“验证不成仍放行”的兼容路径。
- 保存必须持有本轮登记凭证。取消先同步作废凭证，再异步停止 Android 服务；删除与原子保存持有同一锁，旧任务不能恢复已删除声纹。清空聊天不删除声纹，清除本机数据会删除声纹。

说话人验证不是声源分离或活体认证。没有神经目标说话人分离、抗重放或抗克隆模型；多人重叠、感冒、极短唤醒、远场等仍需真实测试，不能作为支付/身份凭证。登记前禁用语音操作，文字聊天不受影响。

## TTS 与回执

- 选择可用中文音色，优先已安装、不依赖网络的音色；首个列出音色不能使用时继续尝试其他已安装音色，最后才使用语言接口；只允许一项合成在途，提前缓存最多两段。
- 使用非空 Bundle。请求拒绝、异步合成失败或超时后受控重连一次，保留失败阶段、返回码、引擎与音色；不重调模型或重放工具。
- 同一 AudioTrack 暂停与恢复；暂停时结束播放参考，恢复时对齐实际时钟，不把未播放音频误当回声。
- 工具结果按调用 ID 独立进入 tool 消息，旧存档缺 ID 时生成稳定本地 ID。账本仍保存，不靠提示词实现幂等。
- 系统播放故障使用 playback_error，保留回答文字，不伪装用户打断。

## 能力与网络

保留一般知识回答、全部原有工具、完整回答与连续工具轮次。服务设置允许账户支持的模型 ID，不设置固定模型白名单或静默替换。简洁要求只作为表达提示。

新增 search_web（公开 Bing RSS 搜索）与 read_web_page（正文分页）。不用隐蔽代理、不发送账户 Cookie。Android 逐跳检查地址、禁止私有网络并固定已验证 DNS 结果以防重绑定；页面超过 2 MiB 或非文本时明确失败。公共搜索无商业 SLA，可能限流、返回验证码或空结果；浏览器跨域仍可能拒绝读取，不能谎称已联网。

## 验证边界

使用 Node 回归、JVM 策略与独立 Android instrumentation。Android 测试覆盖实际 AudioTrack、暂停恢复、测试引擎经系统 TTS 合成文件/故障重连、公开实际说话人录音的 CAM++ 同人/异人比较，以及真实 KWS/VAD/CAM++ 对合成 BLACK 登记和独立回读的联合处理。公开录音和合成音频只放 src/androidTest，禁止进入正式 APK。

测试引擎不是 ColorOS 原厂中文引擎，公开录音不是用户现场录音；无 USB 真机连接，不能宣称已消除用户手机实际故障或达到豆包同等准确率。外放回声、短唤醒、慢速犹豫、旁人插话、锁屏及原厂 TTS 仍需手机验收。只读语义判定额外产生模型请求，网络与模型会影响时延；当前不是端到端语音模型。

### 2026-10-15 开发环境结果

- 全量 Node 回归：546 / 546 通过；TypeScript 无报错。
- Android JVM：55 / 55 通过，包含独立音频包、等待/错误恢复、取消/删除凭证、关键词时间窗及声纹登记策略。
- 整个 App 的 Android Kotlin 编译通过（:app:compileDebugKotlin），包含新增网页模块的自动链接；这不是正式签名安装包。
- 自有 Android 15 模拟器 instrumentation：11 / 11 通过。确实运行 CAM++ 原生推理、TTS 系统接口、AudioTrack 与公开网页网络请求，不是只检查状态字符串。
- 公开同人留出录音的三个余弦分数约 0.555–0.595，异人约 -0.109 至 -0.081；降音量并添加轻微噪声的同人仍匹配。样本量不足以代表用户人群准确率，未测试用户本人的声纹。
- 两个独立留出 640 ms 本人片段通过短模板验证；随后另一说话人的 320 ms 音频包被拒绝，192 ms 尾音不会借用旧主人 PCM。**仍有其他本人短片段被拒绝**，不能用通过的两个样本代表所有短命令。
- Windows 合成的三段 BLACK 开头语句建立个人关键词模板，第四次不同语速的独立 BLACK 回读通过，另一合成音色说同一个词被拒绝。这验证生产组件的可运行性，不代表真人准确率。首次测试确实失败：Kotlin 的关键词 boost 默认值 1.5 与 Python 验证用的 1.0 不同；现已显式统一为 1.0，保留 0.5 关键词概率门槛后重测通过。
- 模拟轮次测试覆盖 wait / respond / ignore 的编排与取消；未调用真实付费模型评测语义判停准确率，也不能据此承诺真实对话自然度。

初版自适应门槛把高度相似的登记样本映射为 0.65，导致留出的同人录音被拒绝；该算法已删除，以模型级工作点替代。旧的识别分段即提交和 VAD 即取消链路已替换。上述为开发验证，非正式 APK 发布或 ColorOS 手机验收结论。
