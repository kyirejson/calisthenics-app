# Harness V2：个人知识库与长期记忆实施

2026-10-02。本地开发版实现；没有推送仓库、部署 Render 或发布手机安装包。原用户档案和设置保持不变。研究报告与 Harness 全量规格不等于全部已交付。

## 使用入口

今日 → 饮食 → 营养助手 → 右上角“记忆”。

- 六题档案：目标、周安排、场地器械、基础、重点与不喜欢的动作、训练限制。最后一题可补充饮食偏好。允许跳过，最后核对保存。
- 档案按减肥控重、街头健身、器械训练分别保存。不自动修改实际训练设置，不把自述当作完成或晋级证据。
- 权限：默认“询问请求确认”；切换“完全访问”自动持久保存。网络同意、设备麦克风授权与执行权限是不同层次。
- 新增上传个人档案、相关旧历史和真实训练快照，旧版联网同意需要对此新用途确认一次；之后按保存状态使用，直到主动撤回。

## 真实已开放的操作

| 工具 | 请求确认 | 完全访问 |
| --- | --- | --- |
| 记住明确的喜好、忌口、需求、过敏 | 核对后保存 | 校验通过直接保存 |
| 添加实际饮食 | 确认草案后保存 | 食品、状态、份量、餐次齐全后直接保存 |
| 替换／调整未吃的推荐菜单 | 预览后确认 | 原有确定性配餐校验通过后保存 |
| 明确修改营养目标、模式、过敏原、活动程度与健康声明 | 偏好草案核对后保存 | 校验通过直接保存；缺项不猜 |
| 记忆页忘记／清空对话控件 | 明确确认 | 点击直接执行 |

模型没有训练计划写工具、饮食删除工具、权限提升工具或自定义食品创建工具。三专题课表、动作组次、覆盖审计与近期实际记录来自现有训练引擎，仅供解释；计划不等于已完成。缺失食品或数量继续询问，不凭空补齐。

随后按用户明确要求移除饮食页 ⓘ 目标记录入口和齿轮营养设置。新增 `set_preferences`：明确营养陈述共用提取器，首先在本机完成，离线也可保存；过敏原增删区分独立偏好与助手记忆来源。健康筛查只有明确声明才完成；热量与宏量目标继续由原有本机引擎计算，不接收模型数值。历史目标快照仍用于历史计算，不再有查看弹窗。详情见 [饮食页简化记录](nutrition-ui-cleanup-2026-10-02.md)。

执行前由本机重新验证真实权限、权限版本、数据基线；同一操作编号和内容只提交一次。业务数据与幂等回执一起保存，模型不能伪造已执行。重复编号改变内容被拒绝。切换权限或修改资料后旧草案失效。

## 记忆存储与召回

- 手机使用独立 SQLite 库、FTS5 索引；浏览器使用 IndexedDB 和中文关键词索引。新增 `expo-sqlite` 原生依赖，手机正式版本须重新构建，不应仅 OTA 更新。
- 最近 30 条是显示页，不是删除阈值。聊天可加载更早对话；保留所有有效原始轮次，不再裁掉超过三十条的历史。
- 本次上下文组合为当前专题档案、已确认事实、最近六轮问答、最多八条相关旧证据和真实训练快照。不是把无限历史全部发送模型。
- 中文二元词、少量别名、专题与本地自然日／自然周过滤。属于确定性关键词检索，不是向量检索、全语义理解或模型自动摘要。
- 老 JSON 历史先迁入数据库，成功后才退出 JSON 保存路径；保留迁移标记，清空后不会再次导入已清除旧对话。
- 历史仅恢复文本，不恢复可执行意图，旧回复不构成执行回执。忌口／过敏／需求优先进入上下文，超出容量明确报错，不静默丢弃。
- 可见助手回复最多 50 个 Unicode 字符；专业原则须引用现有知识摘要，个人档案／课表事实可以不附外部引用。

## 删除、备份与限制

忘记某项事实会删除它及包含该文本的历史问答，并移除相应索引；相关个人档案字段也会清理。已导出的备份不会被远程清理。手动设置的过敏原不自动删去。

跨数据库与档案文档没有分布式事务。删除记忆时档案写入失败会恢复相关归档；若恢复也失败，明确提示导出核对，不报成功。业务已提交而回执文本归档失败时实际业务与持久回执为准，不重复提交。

导出备份包含全部助手历史和轻量档案，读取失败显示归档错误并保留原数据。本次没有新增导入恢复、账号隔离、多设备同步、数据库加密、自动云备份或对卸载／浏览器清理的永久保存保证。设备语音支持仍取决于原有平台能力。

## 验证与上线边界

本次类型检查通过，全项目 **479 项测试通过、0 失败**。旧助手四种浏览器宽度与 V2 两种移动宽度的隔离测试均通过；已检查 320px 实际渲染截图，无横向溢出。

- 类型检查、全项目回归；新增真实 SQLite/FTS5 测试覆盖迁移、超过三十条历史、中文旧记忆、时间范围、删除索引和参数绑定。
- Provider 测试覆盖档案持久化、自动／确认权限、失败回滚、幂等及备份不截断。
- 隔离浏览器、模拟语音和模型，不访问用户数据或付费模型。原助手四种宽度回归；新 V2 两种移动宽度验证六题问卷、重开、140 条 IndexedDB 历史召回、自动记餐、缺项拒绝与忘记清理。
- Render 需要部署本次服务端代码后才支持新的 `harness` 请求；本次没有验证公网真实模型端到端。囚徒私人知识库仍需现有部署侧同步，未新增施瓦辛格来源。
