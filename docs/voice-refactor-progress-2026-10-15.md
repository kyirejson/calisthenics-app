# BLACK 语音重构实施记录

日期：2026-10-15。基线 v1.7.17；本记录描述 v1.7.18 开发改动，不是真机验收报告。用户随后要求直接上传正式更新，不追加检验；正式产物信息以 GitHub Release 为准。

目标手机：用户确认 OPPO Find X8 Pro，ColorOS 16.0.10；不要求 USB 连接。该机型的真实延迟、外放与锁屏结果尚待验收，不从桌面 CPU 或模拟器推定。

## 本轮已替换的内容

- 删除声纹登记、逐包主人验证和对应模型依赖。普通对话不再要求登记，不给模型传 ownerVerified。
- 移除 Android 系统 TTS 生产实现和自动备用；接入固定摘要的本地 MeloTTS 中英候选引擎，MIT 许可随资源分发。
- VoiceCaptureDriver 独立读取麦克风，使用有界队列；识别与合成不在 AudioRecord.read 线程执行。停止后不能因迟到初始化再次开启录音。
- VoiceSessionController 统一控制会话，输入与输出状态独立。空闲 cancel 不再开启收音；迟到结果不能恢复已取消回答。
- 输出改为 MODE_STREAM 音轨、部分写入处理、预填充与实际播放进度；合成/播放独立工作队列，有界预取。
- AEC 改用完整回声抑制后的 capture 输出，不再误把仅线性滤波输出交给识别，也不再按波形相关性整帧静音。
- 首次配置加载与真实配置变更分开，验证标记变化不再取消语音轮次。
- 只有识别草稿真正修订才撤销旧判停；重复 VAD 候选和未变转写不会反复触发同一个远端判断。
- Native 事件带 serviceEpoch/sessionId，服务重建后旧事件不能覆盖新状态。
- 更新通知、设置、提示词、构建资源及测试。移除旧系统 TTS 测试服务和身份专用测试，不保留两套生产主循环。

用户设备上的旧声纹未自动删除，也不再读取或解密。设置中仅保留主动清理旧文件及密钥的入口；训练、饮食、聊天和音乐数据不变。开发打包目录的旧公开 CAM++ 模型已移除，可由原固定下载源恢复，不是删除用户录音。

- Kokoro 中英 int8 首次桌面测试约 14.7 秒生成 4.23 秒声音，没有作为当前引擎。
- Matcha 中文模型的上游页面提示非商用数据限制，没有直接集成。
- MeloTTS 归档 SHA-256：`e58351ed7149f290a54534538badd4077cdbe6fddc964b24d0bee870415d1514`。
- 模型文件 SHA-256：`bf30582eb1b012250a35b1a4a80e7dfbcf8485e7bb9de0d95efbbeef0e4ad86d`。
- 桌面初测“我在”合成约 0.31 秒；后续独立检查约 0.64 秒。17 字样例后测约 2.56 秒、音频约 3.03 秒。并发编译期间明显更慢，不能只拿最优数字宣传。
- 此模型目前约 170 MB，外加词典等资源；删除约 28 MB 声纹模型不能抵消新增体积。尚未生成正式 APK，不能声称安装包已经变小。

可复现脚本：`scripts/check-voice-synthesis.py`。Windows FST 依赖不支持本次中文磁盘路径，使用独立 ASCII 路径快照运行；Android 使用 APK 内的 ASCII 资源路径。

## 开发验证结果

- TypeScript 检查通过。
- 全量 Node 回归 542 项通过；其中新增服务重建事件顺序和首次配置加载不取消语音的回归。
- Android 主工程 Kotlin 编译通过。
- 语音模块 JVM 16 项通过。
- 自有 Android 15 x86_64 模拟器最终 9 项 instrumentation 通过，实际运行本地中文模型、AudioTrack、暂停恢复、取消、极短语音起播、合成失败回执、JNI 重采样及中文语音双讲对照。
- 原有公开样例：BLACK / HEY_BLACK 检出，负样例不检出；上游中文 ASR 样例成功转写。

测试确实抓到流式播放器的起播死锁：写入少量 PCM 后等待播放头，但设备还没达到起播阈值。已加入 API 31+ 起播阈值与旧系统预填充处理，并改为连续有界写入；另补足不足阈值的极短 PCM 静音预填充，不把静音计入已读文字。

声学对照也曾失败：低音量持续纯音混入回声后，AEC3 默认抑制输出仅保留约 4.5% 的该音幅。该结果保留为已知限制，不把纯音宣称为正常人声。随后使用两段实际本地中文合成语音建立双讲测试，不降低人声保留断言：延迟双抽头回声的残余能量比约 `4.33e-6`，插入语音的最佳对齐投影增益约 `0.375`（测试下限 `0.2`）。这只验证固定模拟声学路径，仍有明显幅度损失，不等同于真实人声清晰度或手机抗回声验收。

最终完整 instrumentation 9/9、JVM 16/16；全量 Node 再次 542/542、TypeScript 与 diff 空白检查通过。四种 Android ABI 的本地模块构建通过。这些数字对应最终代码的完整运行；纯音抑制的已知限制单独列出，不包含在人声保留验收结论中。

构建验证位于 `D:/UncoverBuildTools/voice-refactor-20261015`，不覆盖已发布快照，不安装/更新用户手机。不接受新 SDK 协议、不调用付费语音服务。

## 仍未完成，不能宣称整套方案已交付

1. AEC3 已接通完整抑制输出并移除整帧静音，也去掉显式系统 AEC 叠加；但完整声学前端选型、噪声/增益处理、残余回声策略与设备路由对照尚未完成。当前双讲仍有幅度损失，真实外放双讲和自触发不能靠模拟路径测试宣布消除。
2. 用户轮次仍采用本地识别累计与文本语义评估，不是原生音频判停模型；慢速停顿、附和、指向性和真实模型时延待评测。
3. 候选人声目前只短暂降低输出音量，不销毁回答；真正取消仍需语义确认。快速停声/误打断指标尚未经过真人测试，不能宣称已达到豆包交互。
4. 模型文字仍即时展示，但语音交付仍在模型最终回答确认后启动；仅音频合成与播放分段并行。严格的模型增量可朗读通道与多工具轮次协议尚待实施，不能把音频分段说成模型原生边生边说。
5. 前台、锁屏、蓝牙切换、ColorOS 16.0.10 外放长对话和目标手机性能/耗电尚未验收。
6. 用户要求将当前代码直接打包为 v1.7.18 并发布，不追加功能检查或真机验收；发布不能视为上述待办已完成。新增内置模型的正式分发体积以 Release 附件为准。

后续开发优先顺序：声学前端对照与真实播放参考验证 → 模型可朗读增量协议 → 判停/打断与系统生命周期验收。本次应用户要求直接发布当前进展，不发布“全部修复”的声明。
