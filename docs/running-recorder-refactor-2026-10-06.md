# 跑步记录器重构

> 历史记录：这套实现后来被移除，本文不再描述当前代码。2026-10-08 新模块的结构与实际验证范围见 [新版跑步模块](running-map-2026-10-08.md)。

## 保留的 UI

沿用跑步页的地图、里程、时间、平均配速、目标、暂停及结束按钮；只调整真实定位状态，并在发生故障时显示原因。没有增加新的跑步页或替代界面。

## 代码边界

- `src/running/runState.ts`：纯状态计算、定位质量及异常点过滤、暂停计时、历史记录生成。
- `src/running/runRecorder.ts`：应用级唯一记录器，定位订阅、原生任务、权限、草稿存储及保存流程。
- `src/running/RunRecorderHost.tsx`：根部启动、时钟刷新、应用生命周期和更新阻断。
- `src/screens/RunScreen.tsx`：原 UI 及跑步目标编辑，不再拥有定位订阅和里程状态。

## 行为

1. 离开今日、切换页面不会终止记录；所有跑步入口读取同一记录器。
2. 浏览器明确使用 `enableHighAccuracy`、零缓存、15 秒定位超时。
3. 精度大于 50 米的点仅用于当前位置提示，不累计里程；页面显示精度不足。
4. 按定位时间戳排重、拒绝倒序、无效或过期点；过滤异常速度和小幅静止漂移。
5. 暂停以及超过 30 秒的定位断点重新建立起点，不按直线补算漏掉的路程。
6. 原生任务处理后台定位批次；Android 使用用户启动的定位前台服务和持续通知，暂停/结束停止服务。iOS 按权限启用后台记录。
7. 前台定位异常、信号中断、未授权、草稿存储失败有区别明确的状态；回到前台可重建异常定位订阅。
8. 草稿写入 `uncover.running.draft.v1`。定位更新及每 5 秒做检查点，写入串行化；草稿损坏禁止静默覆盖。
9. 浏览器刷新或无有效原生任务的重启恢复为暂停；只保留上次检查点之前的时间，不把关闭 App 的时间算成跑步。
10. 保存使用开始时生成的稳定记录 ID，重试不会创建重复历史。历史写入成功再清草稿，失败仍可继续或重试。
11. 无有效路线的纯计时记录不伪造距离/配速；已有历史结构继续兼容。
12. App 清空数据同时停止定位并清除跑步草稿；记录中阻止 OTA 自动重载。

## 验证与边界

- 新增纯状态/记录器自动测试，覆盖异常点、漂移、定位精度、暂停、断点、稳定 ID、损坏草稿、存储故障、后台任务及没有 UI 订阅的持续记录。
- 浏览器隔离测试覆盖 320/390/650/681/1280 px，保留原布局；额外验证跨页面累计、弱信号提示、刷新恢复及最终草稿清除。
- 已通过 TypeScript 检查、379 项全量测试，以及 Android `:app:compileDebugKotlin`；新增任务模块已参与原生构建。
- 原生新增 `expo-task-manager` 和定位前台服务权限，需要重新构建安装包；旧安装包不能仅靠浏览器更新获得新原生模块。
- 浏览器不能保证锁屏定位；手机后台效果仍需实机授权、锁屏跑步验证。系统强制结束 App 后不承诺持续定位，草稿用于恢复已记录内容。

SDK 依据：[Expo Location](https://docs.expo.dev/versions/latest/sdk/location/)、[Expo TaskManager](https://docs.expo.dev/versions/latest/sdk/task-manager/)，及当前安装版本的 Android `LocationModule.startLocationUpdatesAsync` 权限检查。
