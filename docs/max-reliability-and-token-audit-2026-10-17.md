## 用户九项问题

| 项目 | 审计结论与本轮处理 |
| --- | --- |
| 微信空窗口、0 个控件、反复截图“范围已改变” | 确认旧代码直接用根节点矩形裁图，零矩形必然失败，反复重试没有意义。新增根节点→真实窗口→主显示器的边界回退，截图零矩形按实际捕获图像处理；无障碍加入非重要视图标记、改善应用窗口选择。空树自动尝试本机 OCR，区分空树、连接断开、缺权限和系统拒绝截图。没有在这台用户手机上证明微信发送已恢复。 |
| Shizuku 与开发者选项 | 非 Root 的无线调试/ADB 启动需要开发者选项；Root 可以直接启动。无线配对通常一次，重启后要重新启动 Shizuku；官方建议运行期间不要关闭开发者选项/USB 调试。普通主屏手机控制只需要无障碍，Shizuku 用于已选择的音乐后台虚拟屏幕。 |
| 手机点击慢 | 云模型逐步观察/规划的网络往返是主要等待来源之一。新增模型可保存、查询、参数化运行的常用流程；本机逐步读真实界面再执行，减少每点击一次都调用模型。页面条件或唯一目标不符即停下，返回回执和画面让模型接管。修正公开自定义 URI 被一律强加 BROWSABLE 分类的问题，提高已支持直达入口的可用性；没有硬编码用户联系人、地名、路线或意图路由。 |
| 清后台重开后需要切语音开关 | 旧代码持久化了开关，但缺少 App 重进前台时恢复原生监听服务的入口。增加原生模块创建/前台恢复钩子，已开启且麦克风仍授权时恢复服务；临时启动故障不再把用户开关改成关闭。已有服务不重复启动。 |
| 重复授权 | 已授权的麦克风/通知/Shizuku 不再次申请；保存 App 内同意状态，正常关闭再开启不重复展示说明。断开连接与撤权分别返回，不把空树或 Shizuku 未运行当成所有权限没授予。系统或用户撤权、清除数据、重启后 Shizuku 未启动仍需按真实原因恢复，不能由 App 保证永久系统授权。 |
| 不应接收导航播报 | 原有 AEC 参考是 MAX 自己的 PCM，没有第三方导航音轨，因此不能据此区分导航与人声。新增 Android 播放属性监测：可观察的导航/外部语音播放期间，暂停该时间段麦克风输入进入 KWS/ASR，覆盖录音排队与短回声尾音；不由这些声音触发 MAX 中断。语义判停模型再结合上下文忽略设备播报。没有引入声纹。 |
| 操作后长篇汇报 | 强化短结果提示词，增加 `finish_phone_task`：模型核实后直接输出一句成功结果，失败说明实际阻碍。无需再生成一轮长总结。语音可选择播完摘要再回待机；有新用户话语时保留输入。不会在语音尚未播放时提前退出。 |
| App 不运行时提醒 | 新增 Android AlarmManager + 私有广播接收器 + 高重要性通知频道；模型自行判断内容、日期、时区和重复日，通过工具创建/修改/取消。通知和准时提醒权限只需授予一次；支持一次性与指定星期重复，更新/重启/回前台后重建调度。进程关闭不依赖 JS 或模型；系统“强行停止”会暂停应用，需再次打开。 |
| 缓存命中、流程缓存及用量排序 | 删除开头系统提示中的变化日期/时刻，把投递和执行状态放到历史之后，保留稳定指令和工具顺序。去掉读屏中的重复标签、空字段和默认 false 字段，保留全部返回文字、节点引用、坐标和动作编号。新增真实 API usage/缓存命中/耗时统计，以及 `read_agent_usage`，按工具/请求类别查询。没有伪造历史命中率，也没有截断对话或限制模型工具轮数。 |

## 语音隔离的实际范围

Android 的公开播放状态可报告用途和内容类型；它不提供可任意读取的第三方完整 PCM。标准 AudioPlaybackCapture 也只覆盖满足捕获策略的媒体/游戏/未知用途，不能假定能捕获所有导航声音。因而本轮采用已知外部播报时段的输入门控，没有宣称“已经完整分离任意播放与用户人声”。

代价是：检测到导航播报期间，用户同时说话也可能暂时不被接收，需要等播报停下。地图没有正确标注播放用途、系统隐藏属性、外部设备或另一台手机播放的声音仍需真机验证；语义模型可以辅助，不能从文字证明声音来源。MAX 自己的播报仍走现有 PCM 参考与 AEC，新增模块不替换其播放状态机。

## Token 消耗排序

V1.8.0 没有持久化 API usage，因此无法从仓库还原用户手机的真实账单。以下按源码的潜在输入量与模型往返负担排序，属于静态审计；实际次序由文件长度、历史长度、页面控件数和任务步骤决定。

| 排序 | 操作类型 | 主要消耗 | 本轮措施 |
| --- | --- | --- | --- |
| 1 | 大附件、很长的知识笔记、携带这些内容的后续对话 | 附件/笔记正文和历史完整发送；长文件可超过普通操作数倍 | 稳定上下文前缀，提高可复用部分的缓存机会；保留全文访问能力 |
| 2 | 微信/地图/音乐跨页面多步骤操作 | 每轮带完整历史、工具定义和先前画面；逐次调用模型的输入量累加 | 控件输出压缩、复用已核实流程、本机多步执行、真实公开直达入口 |
| 3 | 多网页搜索与阅读 | 网页默认每页 12,000 字符，最高 24,000，再随历史进入后续请求 | 保留模型自主分页；统计实际消耗供模型选择读多少 |
| 4 | 长历史下的语音语义判停 | 判停模型读取完整历史，正式 Agent 随后还会处理一次；修改草稿可能触发新判停 | 稳定投递状态位置、单独记为 voice_turn_assessment；未增加固定关键词判停 |
| 5 | 饮食新增/修改、训练分析 | 常有读取记录与写入/核实的工具往返；实际数据规模不同 | 共用稳定提示、保留业务幂等与同一模型工具 |
| 6 | 已有媒体会话的播放/暂停、已命中的简单常用流程 | 工具较少、无需多页探索 | 优先实际媒体接口/已验证流程；一句收尾 |
| 7 | 本地事项提醒创建/修改 | 参数确定后一次本地保存与系统调度；到点不调用模型 | 原生准时通知，免去开闹钟 App 的逐步读屏 |

KWS、ASR、VAD、AEC 和内置 TTS 的本机推理本身不消费 DeepSeek API token。判停和业务模型调用会消费。

新增统计只保留最近 500 次请求的计数、类别、时间和耗时，不保存密钥、提示词、屏幕正文或录音。缓存命中率只使用服务实际返回的 hit/miss 计数；缺失时返回未知。可直接向 MAX 询问“查看各操作的 token 消耗和缓存命中排名”。

流程缓存只保存模型选择的步骤与参数结构，默认返回摘要。缓存不是授权，不自动赋予用户意图；每次由模型根据当前请求选择。它不改变音乐后台/主屏模式，不把尚未在对应应用上成功的路径标记为已验收。
