# 统一拍照记餐相机

日期：2026-09-29；仅本地修改，未上传或发布。

## 用户操作

今日 → 饮食 → 拍照记餐。同一取景区内选择食物、营养标签或条码；相机、快门、相册、前后镜头、补光控制共用。切换模式不跳页面、不另开弹窗、不重开已经启动的相机，也不重复索取本次联网同意。

- 食物：拍照／相册 → 食材与份量核对 → 数据库计算 → 确认记录。保留包装自动分流。
- 营养标签：同一快门／相册 → 包装数值核对 → 保存个人食品 → 选择实际食用量 → 确认记录。
- 条码：同一相机实时扫描；Android/Web也可用同一快门或相册读取条码。在同一界面提供输入条码后查询，不另开输入页。只接受校验通过的商品条码，不读取二维码链接。未收录时可切换营养标签；不猜造营养数值。
- 手动添加食品中的“拍营养标签”“扫商品条码”复用相同组件，只限定可用识别模式，不再维护第二套相机实现。

## 代码与生命周期

`src/components/nutrition/FoodCaptureCamera.tsx`是唯一取景／扫描实现。`FoodCameraModal.tsx`只承接识别后的核对、份量与记餐；`FoodImportModal.tsx`只负责手动建库场景的容器与结果交接。旧重复权限、相机和嵌套弹窗代码、样式已移除。

切换模式／关闭／进入后台取消待处理请求；票据和存活检查丢弃迟到结果。即使浏览器扫码检测仍在异步返回，也检查当前模式与前台状态。对同一条码的连续扫描不重复请求；失败可以显式查询重试。仅删除应用生成的相机缓存，不删除相册原图。

食物用`/analyze-photo`，标签用`/read-label`，条码用`/lookup-barcode`；三种后端处理职责保留，不是三套相机。条码查询不依赖视觉模型配置。食品／饮食历史、计算快照和照片保存选择不变，识别结果不自动写入。

## 真机与平台边界

[Expo Camera文档](https://docs.expo.dev/versions/latest/sdk/camera/)规定只能同时使用一个活动相机预览，并支持同一CameraView实时扫码。照片条码扫描在iOS只支持二维码，所以iPhone的商品条码模式禁用相册扫描，用实时扫描或同屏输入；Android/Web保留相册与拍照条码读取。

本项目Expo Camera 57的Web实现也提供扫码与浏览器兼容回退，不另外添加第二套Web相机。浏览器仍需要localhost或HTTPS以及相机权限。Android/iOS真机的权限、对焦、反光、真实条码命中率和扫描速度仍待验收；不可声称已完成真机测试或拍照能精确测量营养。
