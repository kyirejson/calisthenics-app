# MAX 会话历史与缓存优化实施记录

日期：2026-10-17。对应用户批准的 [DeepSeek Harness 调研方案](D:/001号仓库/calisthenics-app/docs/deepseek-harness-cache-plan-2026-10-17.md)。

## 交付结论

已替换模型历史的生成方式：正常新会话不再根据聊天气泡反推模型历史，而是保存实际模型消息，后续请求继续追加。文字、语音共用同一套规则、完整业务工具和持久日志。没有增加关键词业务路由，没有减少模型可选工具，没有固定工具轮数或强制截短回答。

这是代码和本地验证交付，不是正式发布。没有修改版本号、构建 APK、推送源码或上传更新，也没有读取私人会话/密钥、调用收费模型或操作用户手机。

## 一、具体改动

| 原来的问题 | 这次如何处理 | 主要位置 |
| --- | --- | --- |
| 聊天界面能恢复，但模型上一轮实际看到的工具批次、参数格式和中间文字可能恢复不出来 | 保存真实消息：正文、reasoning_content、工具批次/顺序/ID、原始参数字符串和首次提交的结果文字；UI 从日志生成 | promptJournal.mjs、conversation.ts |
| 切换文字/语音会改变前面的规则和工具列表 | 使用固定、深冻结的完整工具声明和统一规则；模式、唤醒状态作为本轮事实追加 | personalTools.mjs、responseStyle.mjs、两个入口 |
| 每轮重复整份个人记忆、变动时间和回执 | 记忆未变化不重复追加，变化时保留新版本；同一请求只记录一次时间/时区/模式；新执行状态追加，不重写旧位置 | promptJournal.mjs、runAgentTurn.ts |
| “没播出来”和“模型没生成”混为一谈 | 原始回答不变；播放失败、听到哪里、被打断是独立事件。播放进度回调只更新 UI，重要边界才写一次日志 | conversation.ts、promptJournal.mjs |
| 流式响应丢失协议字段或连接断开被当成完成 | 保留 reasoning_content；异常断流保存确实收到的有效部分，未完整收到的工具参数不执行；HTTP 请求体过大与模型上下文超限分开报告 | deepseekClient.mjs |
| 长附件反复整篇进入输入 | 附件正文保存一次，提供稳定资料引用；模型能分页或完整读取，不是只允许前几段 | journalStore.mjs、promptJournal.mjs、chatFileTypes.ts |
| 大段知识/网页/记忆结果持续占据上下文 | 这些工具的大正文保存为可回读资料；实时手机界面的节点、快照和操作证据不作头尾截断 | promptJournal.mjs 的 contentResult |
| 同一句慢语音多次判断时，带上过大的画面/附件 | 判停只读已提交对话文字、工具状态和投递摘要；累计识别候选放最后，不写成多条正式用户消息，不执行业务工具 | turnAssessment.ts |
| 长会话只有无限增长或偷偷删消息两种选择 | 提供显式检查点；有已知模型容量且真实输入 usage 达到 75% 时才自动整理旧已完成对话；真实容量报错时允许一次整理后重试。普通短问答不额外调用摘要模型 | modelCapacity.mjs、promptJournal.mjs |
| 取消/崩溃后，不知道操作究竟执行了没有 | 模型调用先提交，再执行工具；区分“未启动”和“已启动但结果未知”。已知真实回执保留；未知结果不冒充失败，不因补历史自动重发 | personalTools.mjs、promptJournal.mjs |
| 迟到的真实回执可能插入下一批工具中间 | 回执事实立即持久保存，在完整工具批次之间才交给模型；旧的未知结果不被改写，新增真实结果用于核对。恢复 UI 时显示最新回执而非重复两条 | promptJournal.mjs |
| 清空对话后旧任务可能写回来或堵住新任务 | 代次使旧写入、旧版迁移和未完成的对话初始化失效；清空先删除提交指针，再删除相关正文。排队任务被清空时释放队列，文字与语音入口顺序接纳；不删除跑步、饮食等独立业务记录 | journalStore.mjs、conversation.ts |
| 看见“命中低”但不知道哪次、为什么 | 每次请求记录匿名身份对应的会话/模型/协议/前缀版本、结构指纹和变化位置；与真实 hit/miss、任务、工具/流程耗时一起查询 | requestShape.mjs、usage.mjs、read_agent_usage |
| “模型开始返回”和“用户开始看到字”没有分开 | 流式请求分别记录首个 reasoning/正文/工具增量、首可见正文、首工具增量的客户端接收时间；没有对应事件就为未知 | deepseekClient.mjs、usage.mjs |

匿名 user_id 在本机生成并稳定复用，不用手机号，也不把它写进提示正文。请求诊断不保存正文、联系人、截图、参数或密钥。结构指纹只是排查用，不是服务端 token 指纹，不参与权限判断或业务成功判断。

缓存命中率使用服务真实返回的 token 加权统计；支持 cached_tokens 别名，缺失或矛盾计数标为未知，不用零值冒充实测。read_agent_usage 增加 requests 视图，可查看单次请求的结构变化和真实计数。

## 二、存储选型与原方案的差异

没有新增 expo-sqlite、WASM 或其他原生依赖。日志逻辑与存储平台分开，由一个 JS 所有者串行提交：

- Android：复用已有 expo-file-system，在 App 私有 max-agent-journal 目录保存分段的不可变事件和资料正文；小提交指针和匿名身份留在现有 AsyncStorage。
- 浏览器：日志、提交指针和正文放在 IndexedDB；旧 UI 存档读取和小身份仍使用现有存储。
- 测试/非 UI 独立调用：只替换存储适配器，不维护另一套模型历史或业务规则。

复核项目已安装的 AsyncStorage 时，发现 Android 默认数据库上限 6 MB，Web 实现使用 localStorage。因此没有把新增长日志继续全部塞进它们。资料分段处理中文和 emoji 跨 UTF-8 边界，不截断 Unicode 字符。

正文先完整写入，再更新提交指针；载入只读取已提交范围。存储失败会报告错误，不拿不完整历史继续执行。它不是“文件和数据库跨介质事务”，也不承诺多进程同时写入；单写所有者和提交指针是本次的一致性边界。进程中断可能留下不参与回放的孤立正文，清空时会枚举本命名空间清除。浏览器容量仍受磁盘和站点配额限制，未做无限容量承诺。

## 三、旧逻辑清理及迁移

已删除正常运行时的 UI 全量存档重写和“从 receipts 重新拼模型工具消息”的路径，也移除了附件正文自动展开的旧 attachmentMessage 帮助函数。

原先的 v1 聊天气泡存档只保留一次迁移入口。迁移完成且新日志已提交后才删除旧存档。旧版没有保存的真实批次和推理内容无法凭空恢复，迁移记录明确标注 legacy；新记录不再走这种重建方式。

保留已有手机、音乐、提醒、饮食、知识库和通用网页工具，不改变原生权限机制、手机点击策略或语音声学前端。已有参数化流程工具仍由模型选择使用，流程命中、实际执行、任务完成分别统计；本轮没有另外建立关键词快捷路由，也没有声称新增了已经实测更快的原生执行路径。

按 work-transparently 规则，清除了被新设计替代的运行路径，而不是在旧历史重建器之外再叠加一层缓存。

## 四、验证结果

1. 全量 Node 回归：629 项通过，0 失败、0 跳过。包含本轮新增的 36 项模型日志/传输/存储测试，以及原有音乐、饮食、提醒、手机与语音协议检查。测试模拟不等于实体手机验收。
2. TypeScript：tsc --noEmit 通过。
3. Web 和 Android JavaScript 导出构建：通过，使用 EXPO_NO_DOTENV=1 和本机临时输出目录，没有读取 dotenv 或发布。Android 的检查确认平台专用存储适配器可以进入 JS 包，不是 APK 构建或原生文件系统真机验收。
4. 隔离 Edge 的真实 IndexedDB 检查：保存 3,000,000 UTF-16 字符、8,000,000 UTF-8 字节资料；刷新后 8 条模型消息完全一致，含原始工具批次、带空格参数和 reasoning_content；全文恢复成功。清空后该日志命名空间记录为 0，独立业务标记保持不变。
5. 原生文件适配器使用注入式文件系统测试：超过 6 MiB 的完整资料不进入共享元数据存储，重启恢复和清空通过。它不是 Android 真机文件系统实测。

复查入口：

~~~text
npm run typecheck
node scripts/test-all.cjs
node scripts/check-agent-browser-storage.cjs <已安装 Playwright 的绝对模块路径> msedge
~~~

浏览器脚本只在 127.0.0.1 临时端口提供四个明确列出的测试模块，使用隔离浏览器上下文，不访问应用现有用户数据，不下载浏览器，不调用模型服务。

## 五、尚不能据此宣称的结果

- 尚未测得真实 DeepSeek 缓存命中率、费用下降比例或手机执行提速幅度；需要正常任务的供应商 usage 和端到端耗时，不能拿结构不变代替命中计数。
- 没有迁移到 Harness 的 Messages/beta 协议，不冒充官方客户端，不额外上传会话日志。仍使用现有 Chat Completions 链路。
- 未知模型 ID 仍可使用，不猜测容量并强制压缩。一次当前任务自身超过服务容量时，不会偷偷删除未完成工具链；会保留记录并如实报告。
- 归档原文和资料全文都可读取，但真正读全文仍产生 token；摘要需要真实模型请求且可能丢细节，原文始终保留读取入口。检查点切换会使前缀变化，不宣传压缩后必然继续命中。
- 本轮没有验证 ColorOS 真机、真实微信发送、锁屏语音、AEC 或提醒进程退出行为，也没有发布正式版。这些现有功能没有被本轮测试重新认证。
- 本地清空只移除本地会话与关联资料，不承诺供应商远端缓存已被立即清除。
