# v1.7.16 · 本地回声隔离与自主倾听

按用户更正后的要求，不使用豆包/火山引擎服务，不新增账号、密钥或费用。保留现有 DeepSeek 模型及所有已授权工具。设计、依赖来源和限制见 [本地实现说明](voice-local-echo-2026-10-15.md)。

## 本轮修复

- 唤醒仅作为输入交给现有 Agent；移除固定“我在”音频、生成器、来源文件、旧提示词及界面占位回复。
- 用本地 AEC3、实际播放参考、声学相关性和连续采样时钟处理回声；VAD 历史状态不再把已经消除的音频当作新的用户插话。
- 继续保留插话前的音频，并取消旧模型请求、停止正在播放的 PCM，隔离旧回调。
- 模型通过 `continue_listening(reason)` 自主选择暂不出声，不用关键词替代语义判断；保留上下文和所有执行回执。
- 隔离生成完成后的迟到请求轮询，避免把“转入播放”误判成取消。
- 补齐独立 AEC 管线的 scoped FTZ/DAZ 浮点保护；否则静音滤波尾部会造成严重 CPU 开销。
- 正确冲刷系统 TTS 重采样尾部，按原音频时长输出 PCM，验证 8/22.05/24/44.1/48 kHz 输入。

## 已完成的验证

- TypeScript 和 533 项 Node 回归通过，含自主倾听、同批工具、去重、迟到轮询和文字同步测试。
- 20 组生成音频回放通过：短句、长答、噪声、压缩、削波、音量/延迟变化、320 ms 延迟、不同或相同合成音色、两档用户音量和实际停止播放的闭环。没有录制真人麦克风或调用生产模型 API。
- 回声场景未触发新的用户插话；真实合成插话按音频时间约 196–292 ms 检测到。这个数值不是手机端到端延迟。
- 每组 DSP 线程 CPU 耗时须小于音频时长的 50%，防止慢于实时的实现被测试掩盖。修复前同一停止播放场景约 40 秒 CPU/10.3 秒音频，修复后约 0.44 秒；不可把前者归咎为普通模拟器调度。
- Android 15 自有模拟器 4 项 instrumentation 测试通过：实际 PCM 播完、重复播放、及时取消、JNI 保留独立输入及多种采样率完整重采样；不是仅断言服务进入倾听状态。
- 四种 ABI 的 native 构建与 11 项语音 JVM 测试通过。完整 APK 另运行原有跑步/音乐 JVM、签名和包内资源门禁。

## 交付边界

应用 ID 不变，Android versionCode 25。必须覆盖安装完整 APK，不能通过网页或 OTA 更新原生音频模块。最终发布流程沿用既有正式签名，校验四种 ABI、模型资源哈希、旧固定音频缺席、测试类不进入正式包及原有 GPS 功能。

没有连接用户 ColorOS 实体手机。外放声学、蓝牙、远场、嘈杂环境与实际耗电仍需要真机验收；同音字识别错误仍可能出现。不宣称已经复制豆包私有实现或达到其完整原生全双工效果。
