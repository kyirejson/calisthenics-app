# Uncover 数据页：模板审计与本地改版

日期：2026-09-28。范围：数据页、成绩派生、曲线、阶梯、训练历史。未改动训练处方、饮食业务或原始训练记录；未上传、发布或打包。

2026-10-08 更新：按用户要求删除历史最佳／反馈连续日卡、月统计／连续训练概览、路线右上角图例和历史底部提示，并删除无消费者的组件与统计函数。当前页面保留动作曲线、日历及默认收起、同一时间只展开一天的图表式训练历史。下面的初版测试数量仅描述当时验证，不代表当前用例数。

## 1. 审核结论与设计

用户提供的 Progress Curve & Workout History 模板适合用作视觉方向：深色背景、荧光绿曲线、上下衔接的阶梯与成绩图、少量关键指标。但模板本身不是数据规则。

当前采用“动作路线 → 真实成绩 → 出勤日历 → 图表式训练历史”的阅读顺序。默认展示当前计划动作，支持切换各阶查看，不会修改训练计划。详细口径放入说明弹层，不在首屏堆叠长文。

| 原实现不足 | 问题与本次修正 |
| --- | --- |
| 没有记录仍绘制示例成绩；单点补出目标终点 | 会暗示不存在的进步。零记录展示空态，一次记录只画一个点。 |
| 手动选高阶即点亮低阶勋章 | 当前设阶不等于通过验收。只按照实际专项验收证据点亮，不反推解锁日期。 |
| 左右比例固定值、无痛天数最低 48、RIR 由反馈猜测 | 没有采集这些数据。移除伪指标；不再额外显示历史最佳或反馈连续日卡。 |
| 日期等距、超高成绩被裁切、纵轴标签与数据比例不同 | 横轴按真实时间间隔，纵轴覆盖真实最大值与参考值，标签和曲线共用坐标变换。 |
| 曲线平滑可能画出不存在的峰值 | 使用单调三次插值，控制点约束在相邻观测值范围内，不外推未来成绩。 |
| 次数、秒、步、米混用；单组能力与日总量混用 | 分单位派生；“单组最佳”和“当日总量”分开；总量模式不显示单组参考线。 |
| 打开训练、重复会话或异常记录进入统计 | 图表、日历和训练历史共用只读有效记录筛选与 ID 去重。 |
| 月份直接加减导致跨年标题错误；日历点不通记录 | 使用 Date 归一化月份，点击日期筛选并展开该日历史。 |
| 整张图抢走滚动手势；历史全量渲染 | 只接管明确的横向选点；保留纵向滚动。训练日历史用 FlatList 虚拟化。 |
| 窗口缩小时浮层沿用旧像素位置、临近日期重叠 | 浮层采用容器内弹性定位，即使尺寸同步过程中也不越界；距离不足时省略中间日期标签。 |
| 静止图或每帧更新组件 | 曲线和阶梯分别从固定底线升起，使用 transform/opacity，不逐帧重绘 React 组件。 |

## 2. 数据口径

- 来源是本机已有 `TrainingSession` / `SessionExercise` / `SetLog`，不写入演示数据。
- 力量训练至少有一个已勾选、正数、有限值的组才计入。次/秒/步须为整数，米可为小数。无效日期、未来时间、结束早于开始、重复会话不重复计入。跑步须有有效的正时长。
- 单组最佳：同一天、同动作、同单位有效组的最大值。当日总量：这些有效组之和；当天多次训练合并成一个真实观测点。
- 优先使用显式 `trainingDate`；没有时才使用开始时间的本地日期，避免 UTC 切片和跨午夜归属错误。
- 真实休息日不补零、不沿用前值冒充新观测。平滑连线只是观测间的视觉连接，不代表中间日期实际练了这些次数。
- 单组参考线来自当前动作的现有验收标准；完整的“组数 × 数值”仍显示在动作标题下。越过单组线不代表完成多组标准或解锁下一阶。
- 阶梯显示相邻三阶路线，支持点击与全阶选择。“当前计划”“已有记录”“验收达标”区分展示。勋章复用进阶页规则：专项记录、稳定反馈、正确单位与组次、需要时有标准确认，符合规则的两次验收至少相隔 24 小时。删除证据会重算，不永久保留虚假勋章。
- 曲线保留实际填写的动作反馈，不把未填写当作无痛，也不据此推断身体健康。
- 训练历史的有效时长包含训练中休息；缺失、非正数或非有限时长单独注明，不假装为零分钟训练。
- 日历绿色表示当天至少有一条明确完成的训练记录，灰点表示只有部分/未明确完成的记录；这不是整日所有额外训练均完成的判断。
- 记录详情只展示实际勾选的组。与上次比较仅匹配同一动作与单位；重复动作条目合并，跳过没有完成的尝试。跑步缺失热量不按距离补造，已有热量也标作估算。
- 筛除只发生在派生层，原始记录不自动删除。用户主动删除需要确认；删除后曲线、最佳、出勤与验收证据同步重算。

## 3. “拔地而起”动效与交互

- 阶梯：640 ms，Cubic ease-out；底线固定，路线升起，勋章随后移动到对应阶梯上方。
- 成绩曲线：延迟 140 ms 后，以 780 ms 从固定底线长到真实高度；渐变面积一同出现，坐标轴和参考线不变形。
- 数值浮层在曲线接近完成时渐显。查看前后记录、拖动选点和窗口尺寸变化不重新播放整图动效；动作、范围或指标变化才重播。
- 曲线支持点击、横向拖动及网页左右方向键；日历日期可进入对应日的训练记录。2026-10-08 已删除曲线底部摘要和前后按钮，纵向滑动仍用于滚动页面。
- 网页横向选点区域使用 `touch-action: pan-y`，原生端按手势方向决定是否接管；图表支持键盘选点和读屏切换操作。
- Web 跟随 `prefers-reduced-motion`，原生跟随系统 AccessibilityInfo 设置；关闭动画时直接呈现最终数据。后台停止入场动画，卸载清理订阅与计时。
- 原生动画使用 Animated native driver，Web 使用对应支持方式；只动画 transform 与 opacity。详见 [React Native Animated 官方文档](https://reactnative.dev/docs/animated) 与 [AccessibilityInfo 官方文档](https://reactnative.dev/docs/accessibilityinfo)。

## 4. 性能与验证方式

- 图表派生缓存，SVG 最多绘制 100 个原始观测点；LTTB 采样保留首尾及全局最高/最低。没有生成替代记录，完整数据仍用于坐标、数值和选点。
- 历史按训练日虚拟化，初始与分批各 6 天；展开详情才显示组次，避免几千条记录同时渲染。
- `npm run typecheck` 检查类型。
- `npm run test:history` 检查空态、单位、去重、日期、日聚合、验收、实际反馈、日历、对比、坐标、极值、单调路径、抽样及秒级时长。已移除月/周统计和反馈连续日的废弃测试。
- `scripts/smoke-progress-web.cjs` 使用全新隔离浏览器存储与合成记录验证真实页面，阻断营养模型接口，不接触用户当前浏览器的数据。覆盖空/单点/多点、升起中间帧与固定底线、删记录后重算、跨年、320/390/681/1280 布局、触屏方向、键盘、动态减少动画设置及刷新持久化。

本次结果：类型检查通过；全套 257 项自动测试通过（其中数据/曲线新增 41 项）；上述浏览器用例全部通过；`git diff --check` 通过。预览入口返回 HTTP 200。安卓真机尚未实测。

## 5. 尚不能凭空提供的能力

1. 目前没有逐组左右侧独立值与真实 RIR 输入，不能恢复模板中的左右比例和 RIR 指标。
2. `profile.levels` 没有完整的设阶/升级事件时间戳。阶梯是当前路线和验收证据，不冒充历史升级时间线。
3. 次数、动作质量和不适均来自用户记录；没有动作视觉评估，不能保证动作标准、左右对称或作出健康诊断。
4. 本次验证是 Web 与类型/业务测试；Android 真机帧率、系统手势与低端设备性能仍需原生包实测，不声称已测得固定 60 fps。

原型截图和浏览器测试数据均为合成数据，不是用户真实成绩。旧 v1 规格中“未练沿用前值”“无数据画零线”等口径已废止，本文件描述当前实现。
